# Dynamic Router 项目架构文档

## 1. 项目概述

### 1.1 项目定位
Dynamic Router 是一个智能路由模块，专门用于手机助手场景下的用户意图识别与任务分类。项目结合手机状态信息、工具定义、用户对话历史，对用户任务进行多维度分类，为下游任务执行提供决策依据。

### 1.2 核心功能
- **意图分类**：从四个维度对用户query进行意图分类
- **工具路由**：根据用户意图选择合适的工具组合
- **任务复杂度判定**：区分简单任务和复杂任务
- **向量检索辅助**：结合向量库进行相似度匹配
- **正则模板匹配**：对特定场景进行快速匹配

### 1.3 技术栈
- **Web框架**：FastAPI + Uvicorn
- **大模型**：Qwen3.5-35B-A3B (MoE架构)
- **推理引擎**：SGLang (支持早停优化)
- **向量检索**：VSearch 向量服务
- **配置管理**：VivoConfigManager (动态配置中心)
- **日志系统**：Loguru

### 2.2 核心设计理念

#### 2.2.1 并发执行策略
项目采用 `asyncio.gather` 并发执行向量搜索和模型推理，通过异步IO最大化利用系统资源：

```python
coroutines = [
    self._vector_search_task(...),      # 向量搜索
    self._get_router_result(...),       # 模型推理
]
if need_dispatch:
    coroutines.append(self.dispatch(...))  # 正则匹配
results = await asyncio.gather(*coroutines)
```

**设计优势**：
- 向量搜索和模型推理并行执行，总耗时取两者最大值而非累加
- 向量搜索设置超时降级机制，不阻塞主流程
- 支持可选的正则模板匹配任务

#### 2.2.2 路由短路优化 (Early Stop)
项目实现了基于 SGLang 的路由短路策略，在模型生成过程中提前终止：

**短路触发条件**：
- 字段1 (工具类型)：`multi`, `chat`, `pend`, `qa`
- 字段2 (意图明确度)：`infer`, `vague`
- 字段3 (指令类型)：`cond`
- 字段4 (执行状态)：`abnormal`

**实现原理**：
```python
STOP_TOKEN_IDS = [
    25429,  # multi
    9398,   # chat
    3613,   # pend
    14992,  # qa
    22846,  # infer
    37753,  # vague
    9464,   # cond
    33418,  # abnormal
]
```

通过 SGLang 的 `stop_token_ids` 参数，当模型生成到特定token时立即停止，避免生成完整4个字段，显著降低延迟。

#### 2.2.3 多维度分类体系

项目定义了4个正交的分类维度：

| 维度 | 字段名 | 可选值 | 说明 |
|------|--------|--------|------|
| 工具调用类型 | `is_use_tool` | single/multi/qa/chat/pend/unsupported/specific | 工具调用方式 |
| 意图明确度 | `is_intent_specific` | clear/lack/infer/vague | 用户意图清晰程度 |
| 指令类型 | `is_special_instruction` | norm/cond | 是否条件触发 |
| 执行反馈状态 | `is_exe_success` | ok/abnormal | 多轮对话执行状态 |

**任务复杂度判定规则**：
```python
is_complex = (
    is_intent_specific in ["infer", "vague"]
    or is_use_tool in ["multi", "chat", "pend", "special"]
    or is_special_instruction in ["cond"]
    or is_exe_success in ["abnormal"]
)
task_type = "complex" if is_complex else "easy"
```

## 3. 数据流转

### 3.1 请求处理流程

```
用户请求 (query, tools, history)
    ↓
[1] 参数提取与预处理
    - 提取工具名称列表 (_extract_tools)
    - 构建查询内容 (_build_query)
    - 构建工具定义 (_build_tools_content)
    ↓
[2] 并发执行
    ├─→ 向量搜索 (_vector_search_task)
    │     - 调用VSearch服务
    │     - 相似度阈值匹配
    │
    └─→ 模型推理 (_get_router_result)
          - 构建Prompt
          - 调用SGLang /generate
          - 解析输出标签
    ↓
[3] 结果融合
    - 向量高分命中 → 直接返回
    - 正则模板命中 → 返回easy
    - 模型结果 → 后处理
    ↓
[4] 后处理
    - 字段校验
    - 跨维度绑定规则
    - task_type计算
    - 特殊场景处理
    ↓
返回结果 JSON
```

### 4.3 向量搜索超时降级
```python
async def _vector_search_task(..., timeout=2.0):
    try:
        query_results = await asyncio.wait_for(
            asyncio.to_thread(gen_llm_vsearch_res, ...),
            timeout=timeout,
        )
    except asyncio.TimeoutError:
        # 超时降级返回空结果，不阻塞主流程
```

## 9. 总结

Dynamic Router 项目通过以下核心设计实现了高效的意图路由：

1. **并发执行**：向量搜索与模型推理并行，最大化资源利用
2. **短路优化**：基于SGLang的早停机制，显著降低延迟
3. **多维度分类**：4个正交维度全面刻画用户意图
4. **动态配置**：支持运行时配置热更新
5. **降级策略**：向量搜索超时降级，保证服务可用性
6. **连接池复用**：HTTP客户端和OpenAI客户端连接池化

这些设计使得系统在保证准确性的同时，实现了低延迟和高可用性。
