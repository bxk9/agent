底层执行层负责将 Agent Runtime 的计划和工具调用转化为真实动作。执行层包括 Agent Skills 调度加载、Tool Skill Search、Agent Skills 管理、审核状态同步、工具调用、安全管理、执行统计、代码执行沙箱、浏览器沙箱、云电脑沙箱、工具管理、MCP、工具事件管道以及沙箱核心保护能力。Agent Skills 管理支持 Skill 发现、分类、安装、卸载、启用、禁用和自定义，使系统可以动态扩展能力；工具调用模块负责工具查询和工具执行；MCP 模块用于接入外部工具和服务，通过统一协议将第三方能力暴露给 Agent；工具事件管道则负责工具事件解析、Schema 校验、风险控制和 Invoke 执行，保证工具调用是一个经过结构化校验和安全控制的过程，而不是简单的函数调用。

执行层中的沙箱能力是复杂任务落地的关键。代码执行沙箱负责代码运行、依赖拉取、项目维护、多语言执行、文件处理和调试测试，适合代码生成、脚本执行、数据处理和自动化测试等场景；浏览器沙箱负责页面导航、元素交互、DOM 提取、截图、OCR、网页检索、表单填写和网页自动化任务；云电脑沙箱则提供更完整的桌面环境，适合软件操作、多应用协同、图形界面任务、长时间运行任务和复杂办公任务。为了保证安全性和稳定性，沙箱体系还提供安全隔离、最小权限、资源限制、快速启动、秒级启停、内存快照、屏幕转发、流式传输、日志积累、成本控制和交互复用等能力，使 Agent 能够在受控环境中执行高风险或高复杂度操作。

### 2.6、小结

该架构的核心优势在于，它不是一个简单的 LLM API 封装，而是一个面向复杂任务执行的智能体操作系统。它通过云网关解决多端接入和统一入口问题，通过 Agent Runtime 解决任务理解、状态管理和多 Agent 编排问题，通过 Context Engineering 解决长上下文、多轮对话和记忆管理问题，通过执行层解决工具调用、沙箱运行和真实任务落地问题，通过安全治理解决权限、审核和风险控制问题。最终，系统能够支撑从轻量问答到复杂办公自动化、代码执行、网页操作、跨设备协同、长周期任务和多智能体协作的完整智能体工作流。

整个流程从 **端侧用户入口** 开始。用户首先在端侧小 V 中输入任务请求，例如让 Agent 完成某个复杂操作、调用本地工具、执行自动化任务，或者发起一个需要云端协同的长任务。端侧入口会将用户请求传递给 **Claw Gateway**。Gateway 作为端侧统一接入层，主要负\责协议接入、请求转发、鉴权校验以及与云侧服务的通信。

在请求进入 Gateway 后，会将任务传递给 **Claw AgentRuntime**。AgentRuntime 是端侧的智能体执行核心，负责管理端侧 Agent Loop、工具调用、上下文状态和执行结果。

端侧 AgentRuntime 在接收到任务后，会先进入本地 Agent Loop 流程。它会根据当前任务判断是否可以直接在端侧完成。如果任务只涉及简单的端侧操作，例如读取设备状态、调用本地能力、执行端侧 Tool 或完成轻量级交互，则会通过 **Claw Tool** 调用本地工具系统。Tool 系统会根据 AgentRuntime 发起的 tool_call 指令，执行对应工具逻辑，并将执行结果返回给 AgentRuntime。AgentRuntime 再根据结果判断任务是否完成，如果完成，则通过 Interaction 和 Gateway 将结果返回给端侧 UI。

如果端侧 AgentRuntime 判断任务需要调用云端能力，例如需要**更长上下文、更复杂的推理、多轮 Agent Loop、云端沙箱执行、浏览器操作、长时间任务、第三方工具调用或云侧模型能力**，则会通过端云通信链路将任务上送到云侧。图中以虚线分隔了 **端侧** 与 **云侧**，端侧的 Claw 通过 A2A 协议将任务发送给云侧的 **云网关**。

云侧流程的入口是 **云网关**。云网关收到端侧上送的任务后，会进行统一鉴权、流量路由、用户身份识别、会话识别和任务分发。随后任务会进入云侧的 **云 Claw 服务**。云 Claw 是云端智能体任务处理的核心服务，它负责承接来自端侧的复杂任务，并组织后续的云端 Agent Loop、工具执行、模型调用和结果回传。

在云 Claw 内部，首先会创建或恢复一个云端任务。任务进入云端后，会生成对应的任务上下文，并进入 **Agent Loop 执行流程**。Agent Loop 会根据当前任务目标、历史上下文、用户记忆、工具能力和执行状态，持续进行“规划、执行、检查、更新”的循环。在云端执行过程中，云 Claw 会与 **记忆系统** 交互。记忆系统主要用于保存用户长期偏好、历史任务信息、Agent 执行过程、阶段性摘要和任务结果。当云 Claw 执行任务时，会先从记忆系统中读取相关历史信息，用于补充上下文；任务执行完成或阶段性完成后，又会将关键结果、操作记录和上下文摘要写回记忆系统。这样可以保证端云协同任务具备连续性，而不是每次都从零开始。同时，云 Claw 会根据任务需要调用 **模型平台**。模型平台为云端 Agent Loop 提供 LLM 推理能力，包括任务理解、计划生成、工具选择、结果总结和下一步动作决策。模型平台并不直接执行任务，而是负责生成推理结果和 tool_call 指令。真正的工具调用和实际操作会继续交给云 Claw 的执行模块或沙箱系统完成。

当模型判断需要执行外部动作时，云 Claw 会进入工具调用阶段。工具调用可能包括普通 API 工具、云端工具、MCP 工具、浏览器工具、代码执行工具或沙箱操作工具。图中右侧的 **沙箱系统** 承担了高风险、高复杂度任务的执行能力，例如浏览器自动化、代码执行、文件处理、环境运行、远程操作等。云 Claw 将工具调用请求发送给沙箱系统后，沙箱系统会在隔离环境中执行任务，并将执行结果返回给云 Claw。

沙箱的整体生命周期如下：首先，每个沙箱启动时候会**挂载轩辕**的文件存储，每个用户的目录通过**用户ID进行隔离**，通过该方式保证了沙箱用户内容的持久化。其次，沙箱环境会初始化 /workspace 目录，该目录下会更新所有的**云端SKILL列表**。此时沙箱就进入了就绪状态，后续**同一用户**执行下个query的时候，则可直接**复用**该沙箱执行任务。最终，当沙箱长时间未使用，则会**自动销毁**以节省整体资源。

沙箱系统在流程中主要解决三个问题：第一，复杂任务需要真实执行环境，例如运行代码、打开网页、操作文件或使用浏览器；第二，执行过程需要隔离，避免影响用户真实环境或云侧主服务；第三，长任务需要可追踪、可恢复、可审计。沙箱执行完成后，会把执行日志、截图、文件结果、命令输出或结构化结果返回给云 Claw。

云 Claw 拿到工具或沙箱执行结果后，会再次进入 Agent Loop 的检查节点。系统会判断当前结果是否满足任务目标。如果结果不足，Agent Loop 会继续调用模型进行下一步推理，并可能再次调用工具或沙箱；如果结果已经满足任务目标，则会进入收尾阶段。收尾阶段包括结果整理、上下文压缩、任务状态更新、记忆写入以及结果回传。

最终结果会从云侧云 Claw 返回到云网关，再通过端云通信链路回到端侧 Claw Gateway。Gateway 将结果传递给端侧 UI，展示结果。对于需要持续执行的任务，云侧也可以将任务状态、执行进度、中间结果或通知消息异步回传给端侧。

## 4、端云任务协同@孙道明

### 4.1、通用场景下，哪些任务适合放在云端

从任务复杂度角度，以下两类任务适合放在云端执行：

**一、涉及沙箱执行的任务**

包括办公类 PPT / Word / Excel 生成，以及其他涉及代码生成、依赖环境安装、代码执行、Shell 脚本执行的场景。

原因：若放在端侧，代码生成在端侧而执行在云侧，中间会产生大量文件传输，消耗用户流量；同时，在端侧向普通用户展示代码生成与执行过程，交互体验过于复杂。

**二、对话轮数较多、上下文长度较大的复杂任务**

> 需要结合技能执行的耗时、流量消耗、内存占用、电量消耗等维度综合评估最终哪些技能放在云端

1、平均执行轮数超过某个阈值（比如10轮）的技能：如深度研究、办公类、财报助手等skill，均放在云端执行。

原因：随着对话轮数增加，端侧内存占用升高、耗电量增大；累积上下文越长，对用户流量的消耗也随之增加。
