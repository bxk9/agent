        .replace("{{TOOLS_SECTION}}", _render_tools_section(tools))
        .replace("{{INTERVIEW_MODE_RULE}}", _INTERVIEW_MODE_RULE)
    )
    # ... 后续逻辑不变
```

**双模式兼容性检查点**：
- `embed_skill_body=False`：公共规则作为 system prompt 的一部分注入
- `embed_skill_body=True`：公共规则不应重复注入（需确认 `{{INCLUDE_COMMON_RULES}}` 只出现在 `_system_prompt.md` 模板中，不出现在各 skill body 中）

#### 4.2.4 从两个 skill 中删除重复内容

在确认差异化分析完成后，从 `resume_opt_head.md` 和 `resume_generator.md` 中删除已抽取的重复内容，改为在 `_system_prompt.md` 中引用：

```markdown
# 系统提示模板

...

{{INCLUDE_COMMON_RULES}}

...
```

### 4.3 阶段三：精简与统一（可选，0.5-1 天）

#### 4.3.1 精简单文件内重复表述（方案 B）

- `<<<...>>>` 规则只在契约第 3 条详细写一次，其他地方改为"详见契约第 3 条"
- `preserve_order` 规则只在自检清单中写一次，其他地方删除

**风险**：LLM 可能不会"回看"前面的定义。建议保留关键规则的重复（作为强化记忆）。

#### 4.3.2 缩小自检机制统一范围（方案 D 缩小版）

方案 C 已实现的 4 项自动补全恰��覆盖了自检清单中最关键的 4 个检查项。因此方案 D 的范围应缩小为"仅覆盖框架层无法兜底的检查项"：

- `template` 校验（框架层仅 WARN 不纠正）
- `resume_content` 格式校验（框架层无兜底）

其余检查项（`preserve_order`/`scope`/`base_resume_json`）已由框架层兜底，自检清单对其仅起"双重保险"作用，可保持现状。

#### 4.3.3 评估 template 补全升级

当前 `template` 校验只有 WARN 日志，无实际纠正能力。需评估是否升级为强制纠正：

| 选项 | 优点 | 缺点 |
|------|------|------|
| 保持 WARN | 不会误覆盖用户意图 | 用户仍会拿到错误结果 |
| 升级为强制纠正 | 确定性修复 | 可能误覆盖用户"确实想换模板"的意图 |

**建议**：保持 WARN，但在 WARN 日志中增加用户提示（如"如需保留原版式，请重新上传文件"），让端侧有机会展示给用户。

## 8. 核心结论

1. **Prompt 规则已经足够充分**，本次事故不是"缺规则"，而是"LLM 不遵守规则"
2. **框架层自动补全是唯一可靠路径**，已实施的 4 项 P0 补全是正确的方向
3. **`template` 校验目前仅告警无纠正**，需在核心结论中明确区分"有纠正能力的补全"与"仅观测的告警"
4. **抽取公共规则是长期可维护性投资**，而非"治本"——当前最紧迫的正确性问题已被方案 C 修复
5. **不要继续堆砌规则**，边际收益已经递减，反而增加 LLM 的认知负担
6. **低成本验证优先**：先建立基线、试点分层标记、观察效果，再决定是否投入架构重构
7. **Prompt-框架层同步机制**是新增的必要措施，防止"改一处忘一处"问题在框架层同构复现
