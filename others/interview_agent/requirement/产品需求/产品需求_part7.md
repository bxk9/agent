### 4.5 阶段四：系统级"感知 → 主动触达 → 跨场景记忆调用"

**核心目标**：

所有原子能力全员上场。首次启用端侧短信/邮件感知、首次启用日历主动写入、首次启用周期化定时触达，让 AI 从"用户来找我"升级为"我主动找用户"。

**安全底线**：

加入日历 / 主动通知前永远先确认用户偏好；不读取与求职无关的短信邮件；不向外部发送任何内容。

**与前三阶段的关键差异**：

阶段一二三都是"用户主动唤起"；阶段四是"系统主动感知 + 主动触达"，⑦ 求职意图感知首次启用，⑥ 记忆从被动调取升级为跨场景上下文自动注入，**文件管理**承担"自动加载历史定制简历/历史错题"的入口角色。

**体验 Benchmark（上线标准）**：

- **识别准**：短信/邮件中的面试邀约 ≥ 90% 准确识别，提取公司/岗位/时间/形式/地点
- **节奏对**：识别后自动询问演练时机；距面试 ≥ 24h 推"模拟面试入口"，距面试 ≤ 2h 推"考前情报卡"
- **跨场景无感**：进入面试模拟时自动加载该公司岗位对应的定制简历 + 历史错题 + 历史模拟记录，**无需用户重新粘贴**
- **失败诚实**：识别失败 / 时间冲突 / 历史无数据时，明确告知"未识别到面试时间，是否手动添加？"，不伪装成功
- **触点合理**：连续忽略 N 次自动降级触点（原子通知 → 静默到负一屏）
#### 典型 Query 1：面试通知 → 自动入日历 → 演练规划（主动触发）

> "刚收到字节的面试短信，帮我安排好准备节奏"（或无 Query，由短信/邮件感知自动触发）

| 步骤 | 动作 | 调用能力（能力 + 具体内容） |
| --- | --- | --- |
| 1 | 端侧通知感知 | ⑦ 求职意图感知与主动触达 - 端侧扫描短信/邮件，识别"面试邀请/笔试通知/复试/offer"等关键词 |
| 2 | 字段提取 | ⑦ 求职意图感知与主动触达 - 提取公司 / 岗位 / 时间 / 形式（电话/视频/现场）/ 地点 / 面试官 |
| 3 | 自动写入日历 | ⑦ 求职意图感知与主动触达 - 调用 `calendar.write`，事件标题"XX 公司 - YY 岗位 一面" |
| 4 | 历史档案查询 | **文件管理** + ⑥ 求职记忆 - `file.query(字节, *)` 检查是否已有该公司历史简历/JD/模拟记录 |
| 5 | 演练询问 | ⑦ 求职意图感知与主动触达 - 原子通知卡片：演练时机选项（考前 1 天 / 2 小时 / 自定义 / 不用了）；附带"已为你找到字节简历 v3 + 历史错题 8 题" |
| 6 | 演练计划写入日历 | ⑦ 求职意图感知与主动触达 - 用户选定后写入"模拟面试提醒"事件，偏好沉淀到 ⑥ 记忆 |
| 7 | 任务实例化 | **多轮对话连接** - 为该面试事件创建任务实例，绑定历史档案 + 演练计划，供后续步骤接续 |

#### 典型 Query 2：考前情报卡（定时触发）

> "明天面腾讯，2 小时考前给我推一份重点速览"（或由阶段四 Query 1 沉淀的演练计划自动触发）

### 4.6 阶段五：记忆反哺——让简历与面试越用越准

**核心目标**：

把前 4 个阶段沉淀的记忆数据反向注入到简历改写与面试模拟的入口，让用户**每次进入场景的初始上下文都是个性化的**——不是 AI 替用户改，而是让起点就高。

**与前 4 阶段的关键差异**：

阶段一~四是"用户主动触发 → AI 处理 → 输出结果 → 写入记忆"的正向流；阶段五是"记忆 → 自动注入 → 改变下一次 AI 处理的初始状态"的反向流。所有反哺过程对用户**无感、不打断、可关闭**。

**体验 Benchmark（上线标准）**：

- **改写有继承**：用户进入"投相似岗位"时，自动推荐"复用 X 版本 + 微调 Y 模块"，省去从头改写
- **模拟有重点**：新一轮模拟自动按"用户薄弱考点权重"加权出题，**优先复测**而非随机出题
- **追问像本人面过的**：模拟面试官追问风格沿用历史真实面试中提炼的特征
- **触达有节奏**：演练偏好沿用历史档位，无需重复询问；连续忽略自动降级触点
- **风险项闭环**：真实面试中翻车的 bullet **反向标记**到简历，下次改写优先重构
- **强项保护**：不在已掌握考点上反复出题，把模拟时间留给真薄弱项
- **档案归档**：用户标记"已 offer / 已拒"后，整个公司岗位文件夹打包为求职档案
#### 典型 Query 1：相似岗位复用历史改写

> "我之前给字节抖音电商投过简历，这次投快手电商也用类似版本"

| 步骤 | 动作 | 调用能力（能力 + 具体内容） |
| --- | --- | --- |
| 1 | 解析意图 | ① 意图理解 - 槽位：目标公司=快手；目标岗位=电商；动作=复用历史改写 |
| 2 | 调取相似版本 | **文件管理** + ⑥ 求职记忆 - `file.query(标签=电商产品)` 检索历史定制版简历，按相似度排序 |
| 3 | 公司画像差异分析 | ① JD 与公司画像构建 - 对比字节抖音电商 vs 快手电商画像差异（业务侧重 / 用户群 / 技术栈 / 价值观） |
| 4 | 推荐"复用 + 微调"路径 | ② 简历解析与对齐诊断 - 输出"哪些 bullet 可直接复用 / 哪些需要按差异点微调"清单 |
| 5 | 增量改写 | ③ 简历定向改写 - 仅对差异点 bullet 调用 `resume.rewrite_bullet`，保留复用部分原文，生成新定制版 |
| 6 | 落盘 + 关联 | **文件管理** - 新版本与"字节抖音电商"版本通过 `file.link(派生关系)` 关联，方便后续追溯演变 |

> "上次面字节被追问数据口径答不上来，帮我看看简历哪里需要重写"

| 步骤 | 动作 | 调用能力（能力 + 具体内容） |
| --- | --- | --- |
