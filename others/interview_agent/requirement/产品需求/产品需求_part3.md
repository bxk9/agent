#### 需求 1：自动扫描本地文件作为简历生成基础（升级）——电脑文件扫描依赖pc claw整体打通

| 维度 | 详细说明 |
| --- | --- |
| **现状** | 简历生成需用户主动上传 PDF / Word / 图片 / 文本，存在"用户记不清简历放哪儿、找不到旧版本"的体验断点 |
| **输入** | 1. **本地文件扫描范围**（待评估授权）：<br>手机端微信文件 / QQ 文件 / 系统下载目录 / 文档目录；<br>PC 端 桌面 / 下载 / 我的文档 / OneDrive 等常见目录<br>2. **文件类型筛选**：.pdf / .doc / .docx / .png / .jpg<br>3. **文件名/内容关键词**：简历 / Resume / CV / 个人简介 等<br>4. **用户授权范围**：首次使用需用户明确授权扫描目录，可逐目录开关 |
| **处理逻辑** | 1. **目录白名单扫描**：仅扫描用户授权目录，不全盘检索<br>2. **文件命中判定**：文件名关键词 + 端侧 OCR/解析后正文关键词双重判定<br>3. **多版本去重**：按修改时间 + 内容哈希识别同一份简历的多个版本，呈现"最近修改的优先"<br>4. **隐私端侧处理**：所有扫描与解析在端侧完成，云端只接收用户确认上传后的脱敏摘要<br>5. **兜底策略**：扫描失败 / 用户拒绝授权 → 退化为"主动上传"路径，不打断主流程 |
| **输出** | - **本地候选简历列表**（路径 / 文件名 / 修改时间 / 摘要预览，按相关性排序）<br>- **用户确认动作**：选择某份作为基础简历，或一键合并多份信息<br>- **错误码**：`SCAN_DENIED`（用户拒绝授权）/ `SCAN_NO_RESULT`（无命中）/ `SCAN_TIMEOUT`（超时） |
| **本期判断** | **待定**。价值高（降低素材提供成本），但涉及端侧文件读取权限范围与合规评估，需先完成技术调研。<br>**本期保留"主动上传"为兜底**，调研结论确定后增量上线 |
| **依赖** | 端侧研发：文件扫描 SDK 与权限弹窗；法务：用户授权文案与隐私合规评估 |
