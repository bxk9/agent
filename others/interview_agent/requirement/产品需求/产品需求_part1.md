## 1：我们解决用户什么场景下的什么问题

### 1.1 目标人群

| 人群层级 | 人群类型 | 特征描述 |
| --- | --- | --- |
| 牵引人群 | 应届毕业生 / 职场新人（0-3 年） | 求职频次高、缺乏经验、对"如何写简历、如何答面试题"有强诉求；对 AI 辅助接受度最高，最能反哺产品打磨 |
| 辐射人群 | 跳槽白领（3-8 年互联网/泛白领） | 跳槽周期长、对岗位匹配度敏感、愿为高质量结果付出时间；口碑传播力强 |
| 辐射人群 | 跨行业转型 / 高P 跳槽者 | 深度个性化需求、单次求职决策成本高，对"对齐式反馈"价值感知强 |

### 1.2 核心场景与痛点

我们围绕用户求职的**全生命周期**（投递前 → 面试前 → 面试中 → 面试后），解决以下四大核心问题：

| 场景阶段 | 用户场景描述 | 核心痛点 | 痛点本质 |
| --- | --- | --- | --- |
| **投递前·简历生成/包装** | 用户拿到一份心仪 JD，要写简历，或把通用简历改成"为这家公司这个岗位定制"的版本，但不知道该突出什么、弱化什么、用什么词 | **不知道怎么写/改什么、改成什么样**：自己看不出简历与 JD 的 gap，缺少"对标优秀简历"的参照 | JD 解析 + 公司画像 + 优秀样例三方信息缺失，导致改写无锚点 |
| **面试前·准备与模拟** | 用户知道下周二面试字节产品岗，但不知道会问什么、自己答得怎么样、哪里需要补 | **准备没抓手、练习没反馈**：刷面经像无头苍蝇；自己对镜子讲一遍既不知好坏也不知差距 | 无个性化题库 + 无对齐式反馈机制 |
| **面试后·真实复盘** | 用户面完一场真实面试，凭感觉觉得"答得一般"，但具体哪些题答得不好、当时该怎么答更好，全靠回忆 | **复盘靠脑补**：真实表现没有客观回放，错题没沉淀，下一场还在同一个坑里栽 | 缺乏录音转写 + 答案重评 + 错题沉淀闭环 |
| **投递前/面试前·感知触达** | 用户在 求职软件 浏览了某条 JD 很久；或邮箱/短信收到了面试邀约通知，想不到可以用AI更好的准备面试 | **AI 服务介入太晚**：用户已经焦虑了才想起来找工具，错过黄金准备窗口 | 缺乏跨 App 行为感知 + 主动触达机制 |

### 1.3 我们的差异化定位

> **「简历面试 Skill」是蓝心小V Pro 的求职场景 Skill 群，定位为系统级个人化求职陪跑助手。**

与三方求职 App / 通用 AI 工具受限于沙盒和单点能力不同，小V 作为系统级 AI 助手，天然具备：

- **权威信源**（接入 BOSS 直聘 JD/公司数据、牛客真题与面经，让 JD 解析、公司画像、面试题库都站在一手数据之上，而非通用大模型输出）
> 豆包已有牛客、boss等信源

- **记忆**（跨场景沉淀求职履历池：投递记录、面经、错题本、个人画像）
- **跨场景闭环**（简历改写 → 面试模拟 → 真实复盘 → 错题回炉，所有数据互通）
- **屏幕感知**（跨 App 识别 JD 浏览、面试通知、招聘软件履约动作）
- **多触点主动触达**（原子通知 ，在面试前主动唤起准备）
- **端云协同**（端侧 OCR/ASR 保护隐私，云端复杂推理保证质量）
从而实现三方产品无法提供的 **"感知 → 包装 → 模拟 → 复盘 → 沉淀"全链路求职闭环**。

### 1.4 产品契约（全场景遵守）

| 契约 | 说明 |
| --- | --- |
| **对齐式反馈，不打分** | 不输出"你这条 7 分"这种评分，只输出"和 JD 的对齐项 / 漏掉项 / 待补强项"，把判断权留给用户。所有结论以"参考"措辞呈现，避免"高危/中危/翻车/顽疾"等定性标签 |
| **不自造数字** | 简历或回答中不存在的具体数字（转化率、用户量、营收等）一律不补充；只能基于用户已说出的事实做表达对齐与结构补强 |
| **个性化优先，模板兜底** | 所有产出基于用户简历 + JD + 公司画像 + 历史求职记忆生成，无信息时才退化到通用模板，并明确告知"参考度有限" |
| **隐私端侧优先 · 原文不外传** | 简历原文、录音原文、面经全文等敏感数据端侧处理，云端只接收脱敏摘要；任何调用前向用户明示数据流向 |
| **可追溯** | 每条改写、每道题、每条复盘建议都标注依据来源（来自 JD 第几条 / 来自公司画像哪个维度 / 来自哪条面经） |
| **情绪优先于结论** | 用户表达焦虑/疲惫/受挫时，先共情再给方案；长流程结束先肯定亮点+时间锚点+松弛节奏，再谈待补强方向；用户可随时说"跳过/休息"而不被追问 |
| **柔性免责** | 涉及主观判断（公司画像/面经画像/答题参考路径）时主动声明"仅供参考"；面经数据 < 5 条时标注"参考度有限"，不掩饰不确定性 |
| **度量盲区诚实** | 系统无法识别非语言信号（语速/停顿/眼神/紧张度），相关维度不评价、不暗示，避免让用户为不存在的信号焦虑 |

## 2：我们的解决方案需要什么原子能力

基于上述场景痛点的拆解，整体解决方案由以下 **7 项原子能力** 支撑：

| 序号 | 原子能力 | 能力定义 | 解决的场景痛点 | 优先级 | 商务/外部依赖 |
| --- | --- | --- | --- | --- | --- |
| ① | **JD 与公司画像构建** | 解析 JD 关键要素（职责/硬技能/软技能/隐性偏好），并基于公司公开信息构建"公司基底 + 岗位人才偏好"的多维画像 | 不知道改什么 / 准备没抓手 | P0 | ⚠️ 招聘网站反爬，需 BOSS / 猎聘等数据合作<br>or电脑claw的能力，让电脑去浏览 |
| ② | **简历解析与对齐诊断** | 解析用户简历结构化字段，与目标 JD + 公司画像做对齐分析，输出"匹配项 / 漏项 / 弱项 / 风险项"四象限诊断 | 不知道改什么 | P0 | 优秀简历样例库需合作或自建 |
| ③ | **简历定向生成/改写与渲染** | 基于记忆、用户输入信息生成简历，基于诊断结果对简历条目（bullet）做定向重写、整体编排，输出 diff 视图与可下载的定制版简历 | 不知道改成什么样 | P0 | 无重大依赖 |
| ④ | **面试题库生成与模拟对话** | 基于 JD + 公司画像 + 简历生成个性化题库，支持文字/语音多轮模拟面试，对每个回答做对齐式反馈 | 准备没抓手 / 练习没反馈 | P0 | ⚠️高质量面经库需合作 |
| ⑤ | **真实面试录音复盘** | 接收用户上传/端侧录制的真实面试录音，本地 ASR 转写、对话切分、按题给出"如果重答会怎么答"的对照建议 | 复盘靠脑补 | P1 | ⚠️ 需确认是否支持实时电话外呼/通话录音<br>当前方案为事后录音上传<br>or录音机捐赠skill |
| ⑥ | **求职记忆与错题沉淀** | 将简历版本、JD、面试题、真实回答、复盘建议统一沉淀到记忆，构建错题本与遗忘曲线复习 | 错题不沉淀 / 跨场景断裂 | P1 | 无重大依赖 |
| ⑦ | **求职意图感知与主动触达** | 通过短信/邮件感知用户的面试邀约、投递动作，判断求职意图并通过原子通知/负一屏主动推送 Skill 入口 | AI 介入太晚 | P0 | 端侧感知能力依赖系统层授权 |

> ⚠️ 标识：依赖外部商务合作或系统框架升级，会影响落地节奏；不影响主链路 Demo 跑通。 自动投递功能不在本期范围（受系统框架与三方 App 限制）。
