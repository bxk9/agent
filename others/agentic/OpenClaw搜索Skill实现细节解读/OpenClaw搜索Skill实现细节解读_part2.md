OpenClaw 运行时收到大模型的工具调用请求后，开始初始化`web_search`工具，并完成一系列前置检查，保证流程的稳定性和效率：

1. **Provider 自动检测**：遍历配置的搜索 Provider，按照优先级顺序检查已配置的 API 密钥，选择第一个可用的搜索后端，比如本次检测到 Brave Search 的 API 密钥已配置，选中 Brave 作为本次搜索的 Provider
2. **缓存命中检查**：根据查询词、过滤参数生成缓存 Key，检查本地两级缓存中是否存在相同的、未过期的缓存结果：
  1. 如果存在缓存结果，直接读取缓存内容，跳过后续的 API 调用步骤，大幅提升响应速度
  2. 如果未命中缓存，继续后续流程
3. **限流检查**：检查当前用户和全局的请求速率，是否超过了配置的限流阈值：
  1. 全局默认：30 次搜索 / 分钟、60 次页面抓取 / 分钟
  2. 用户级默认：5 次搜索 / 分钟
  3. 如果超过限流，则进行等待，或者触发降级逻辑，切换到无密钥的 DuckDuckGo 搜索源
4. **参数标准化**：将通用的工具参数，转换为当前选中 Provider 的专属 API 参数，比如将通用的`freshness`参数转换为 Brave Search API 要求的`country`、`language`、`safesearch`等参数，屏蔽不同 API 的参数差异 。

### 步骤 4：搜索 API 调用与结果标准化处理

1. 封装 HTTP 请求，调用 Brave Search 的 Web Search API，携带 API 密钥、标准化后的参数，同时设置 30 秒的请求超时
2. 收到 API 返回的原始结果后，进行多维度的结果处理：
  1. **格式标准化**：将 Brave 返回的私有格式，转换为 OpenClaw 统一的`SearchResult`结构化格式，保证不同 Provider 的结果格式统一
  2. **结果去重**：对结果的 URL 进行哈希去重，移除重复的搜索结果
  3. **来源多样性过滤**：按照配置的规则过滤结果，保证结果最少来自 3 个不同域名，单个域名最多返回 3 条结果，避免单一来源的信息偏差
  4. **安全合规过滤**：检查结果的域名是否在黑名单中，检查结果内容是否包含违规内容，过滤恶意、钓鱼站点的结果
3. 将处理后的结果，写入本地缓存系统，设置 15 分钟的 TTL，方便后续相同查询的缓存命中 。

### 步骤 5：多轮搜索决策与迭代

1. 工具将处理后的标准化搜索结果返回给大模型
2. 大模型对结果进行分析，判断当前的结果是否足够回答用户的原始问题：
  1. 如果结果已经覆盖了问题的所有要点，比如已经有了各个主流 RAG 框架的评测数据、功能对比、性能数据，则直接进入下一步的内容提取阶段
  2. 如果结果不足，比如只有部分框架的信息，或者信息不够深入，大模型会生成新的子查询，比如`"LangChain RAG 2026 最新评测"`、`"LlamaIndex RAG 2026 性能对比"`，重复步骤 2-4，发起多轮搜索
  3. 系统最多支持 3 轮搜索，最多返回 30 条总结果，避免无限制的搜索消耗

### 步骤 6：深度内容提取

1. 大模型从所有的搜索结果中，筛选出最相关的 2-3 个高价值结果，比如某个权威技术博客的评测文章、框架的官方更新文档
2. 自动调用配套的`web_fetch`工具，对这些页面进行深度内容提取：
  1. 发送 HTTP 请求获取页面的原始 HTML 内容
  2. 使用 Readability 算法解析 DOM 结构，自动识别正文区域，过滤导航栏、广告、侧边栏、评论区等无关内容
  3. 将 HTML 转换为干净的 Markdown 格式，适配大模型的输入格式
  4. 自动截断过长的内容，保留最相关的核心部分，默认最大内容长度 5000 字符
  5. 如果是反爬站点（如微信公众号、知乎），普通提取失败的话，自动降级到 MinerU 第三方解析服务，保证内容可以正常提取
3. 将提取后的干净页面内容返回给大模型 。

### 步骤 7：答案生成与引用整理

1. 大模型将所有的搜索结果、提取的页面内容，整合到对话上下文中，作为生成答案的参考信息
2. 基于这些参考信息，结合用户的原始查询，生成自然语言的答案：
  1. 整理各个 RAG 框架的对比信息，包括性能、功能、适用场景、优缺点
  2. 自动整理引用来源，将答案中的每个结论，对应到对应的搜索结果链接，保证答案的可追溯性
3. 生成最终的回答内容，包含自然语言的通顺答案，以及对应的引用来源列表 。

### 步骤 8：结果格式化与返回

1. OpenClaw 运行时将生成的答案，根据用户的使用渠道进行适配格式化：
  1. 如果是终端用户，直接返回纯文本 + 可点击链接
  2. 如果是 Discord 平台，自动转换为 Embed 卡片格式，展示搜索结果的摘要
  3. 如果是 Slack 平台，自动转换为 Block Kit 结构化格式，支持富展示
2. 将最终的内容返回给用户，完成整个端到端的流程 。

---

## 六、总结

OpenClaw 的搜索能力体系是一个分层的架构：

1. **底层**：内置的 web_search 工具提供了标准化、通用的搜索基础能力，通过插件化 Provider 支持多种搜索后端，同时内置了查询优化、结果处理、缓存、安全等通用能力
2. **上层**：生态中的扩展 Skill 基于底层能力，针对不同场景进行增强，比如深度搜索的多源聚合、意图评分，代码搜索的本地文件检索等

这种架构既保证了通用搜索能力的开箱即用，又支持针对特定场景进行深度定制，让智能体可以高效、准确地获取外部信息。
