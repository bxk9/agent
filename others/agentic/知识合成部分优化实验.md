# **知识合成部分优化**

> **核心理念：** 搜索结果不能直接灌入模型，需要经过**显性信源标注 → 模型思考评分 → think 反思校验 → 知识合成**四阶段后处理流水线，减少知识信息错误。

### **3.1 显性信源标注（帮助模型做多信源校验）**

**现状问题：** 当前 `_format_search_results_for_llm` 虽然输出了来源和时间，但信息扁平化，模型难以判断"同一事实是否有多个来源佐证"。

**优化方向：** 在传给模型的搜索结果中，**显性注入信源元信息**，让模型能直观感知"多源一致"还是"孤证"。

### **3.3 Think Tool 反思搜索结果**

**核心思路：** 利用已有的 `think` 工具，在搜索结果返回后、生成最终回答前，插入一轮**反思环节**，让模型主动审视搜索质量并决定下一步策略。

#### **3.3.1 反思触发机制**

```
搜索结果返回
    ↓
[自动注入反思指令] → 触发 think tool
    ↓
think 输出反思结论：
  - 搜索结果是否覆盖了问题的所有方面？
  - 是否存在信息矛盾？
  - 是否需要补充搜索？搜什么？
  - 信源质量如何？是否有足够的权威来源？
    ↓
根据反思结论 → 继续搜索 / 直接回答
```

#### **3.3.2 反思 Prompt 注入**

在 `ai_search` 工具返回结果时，附加反思引导：

```python
SEARCH_REFLECTION_SUFFIX = """
【请在回答前先调用 think 工具进行反思】
反思要点：
1. 以上搜索结果是否充分回答了用户的问题？缺少哪些方面？
2. 不同来源的说法是否一致？如有矛盾，哪个来源更可信？
3. 信源质量如何？是否过度依赖单一来源或低质量来源？
4. 是否需要补充搜索？如果需要，应该搜索什么关键词？
5. 给搜索结果的整体质量打个分(0-100)，并说明理由。
"""
```

升级现有 `think` 工具，动态调用, 只在搜索结果特别差quality_score很低的时候进行调用 ：

@tool
def think(reflection: str) -> str:

​

    1. 搜索结果返回后，评估信息充分度和质量
    2. 发现信息矛盾时，分析可信度
    3. 决定是否需要补充搜索
    """
    # 尝试从反思文本中提取结构化信息
    quality_score = extract_quality_score(reflection)  # 正则提取分数
​
    session._push_event({
        "type": "tool_end",
        "tool": "反思",

                else f"💭 {reflection[:80]}..."
    })
​
    log_info(

### **3.4 知识合成策略**

**现状：** 前按搜索结果数量分级，简单拼接传给模型。

**优化方向：** 按信源交叉验证、主题聚类、冲突检测、动态阈值四个维度升级。

#### **3.4.1 按搜索源交叉验证合成**

**核心思想：** 多个独立搜索源都确认的知识，置信度更高；仅单一来源的知识需标注为"待验证"。

#### **3.4.2 按主题聚类合成**

**场景：** 搜索"AI 行业最新动态"返回 20 条结果，涉及多个子话题（大模型、芯片、政策、应用）。按主题聚类后再分别合成，输出结构更清晰。

#### **3.4.3 冲突检测与显性标注**

**核心思路：** 不同来源对同一事实的描述可能矛盾（如数字不一致、观点对立），需检测并显性标注给模型，而非让模型自行发现。

#### **3.4.4 动态阈值：按意图类型调整**

**核心思想：** 不同意图类型对搜索结果质量的要求不同，阈值/策略应动态调整。
