> **统一口径：** 以下耗时均为 Agent 内部耗时（不含中控调度），端到端耗时单独标注。
> **名词说明（供参考）：**

- **端到端耗时**：用户发出问题 → 屏幕出现第一个字的完整等待时间
- **Agent 内部耗时**：AI 模型处理阶段的耗时，不含前后链路
- **TPM 模型**（Tokens Per Minute 吞吐量版本）：豆包推出的一种**高吞吐、低延迟**的模型部署方案，同等效果下响应速度更快、成本更低
- **TTFT**（Time To First Token）：首字时延，即用户等到第一个字出现所需的时间，是衡量体验的核心指标

## **一、版本演进**

### **V1 初始版本 — 11s（Agent 内部）**

- **架构**：双节点模式（先用一个模型推理判断、再用另一个模型汇总答案），需要调用两次大模型。
- **瓶颈**：即使 AI 已经判定"不需要再搜索了"，还是必须再调用一次汇总模型生成最终答案，多了一次 AI 调用，白白浪费时间。

### V2 单节点 + 模型替换 — 3s（Agent 内部）

| **优化项** | **具体做法** | **节省时间** |
| --- | --- | --- |
| **去掉多余的 AI 调用** | 改为单节点模式：AI 判断"无需继续搜索"时直接给出答案，不再额外调用汇总模型 | 节省约 5s |
| **非计算类问题换更快模型** | 将原来的 Doubao-Seed-2.0-pro（约 5.7s）替换为 **Doubao-Seed-2.0-lite-TPM**（约 2.3s）。TPM 版本是专为高速响应优化的模型，相同效果下首字更快 | 节省约 3s |

## **二、V5 后续优化方向**

> **说明**：「收益上限」= 该策略在不掉准 / 不掉召前提下，理论可压缩的耗时空间。   
> **基线**：V4 Agent 内部 2.4s + 中控 1.9s ≈ **4.3s 端到端**。

| **#** | **优化方向** | **关键手段** | **收益上限** | **风险 / 边界** |
| --- | --- | --- | --- | --- |
| 0 | **模型替换** | 计算类（占比 23%）：Qwen3-Max 首字 4.4s → Doubao-Seed-2.0-lite-TPM 首字 2.5s | **-1s ~ -2s** | 计算类效果可能下降，需 A/B 验证 |
| 1 | **检索源优化** | 当前火山（766ms）与百度（1,217ms）并行，可优先使用火山单一源或异步截断慢源。[5个搜索源效果初步评估](https://docs.vivo.xyz/s/RZtQfwPU) | **-0.2s ~ -0.5s** | 单一检索源可能降低召回率 |
| 2 | **检索剪枝（Pre-Search Pruning）** | ① query 改写数 N → 1-2 个；② 召回 top-6 → top-3 | **-0.2s ~ -0.5s** | 检索覆盖度有所下降 |
| 3 | **Prompt 精简 + 前缀缓存** | ① 去除冗余示例；② 固定 system prompt 启用 KV 前缀缓存（火山显式缓存可提升 8% TTFT）。[缓存数据参考](https://docs.vivo.xyz/detail/office/020114711733?sheetIndex=1) | **-0.3s ~ -0.5s** | 显式 cache 与 TPM 因调度链路和付费模式不同，暂不支持同时使用（需推动模型侧支持） |
| 4 | **提前搜索（Pre-fetch）** | 用户输入未完成时提前触发搜索意图预判，并发发起检索 | **-0.3s ~ -0.8s**（预估） | 依赖前端意图预判准确率；误触发率需控制 |
| 5 | **答案缓存** | 对高频 / 相似 query 缓存结果，命中时直接返回 | **-1s ~ -2s**（高频 query） | 缓存命中率依赖流量分布；实时性内容不适用 |

### **综合收益上限估算**

| **维度** | **当前（V4）** | **理论下限（叠加 #0~#5）** | **备注** |
| --- | --- | --- | --- |
| Agent 内部耗时 | 2.4s | **~1.5s** | 优先级有先后，效果需验证 |
| 端到端总耗时 | 4.3s | **~2.4s ~ 3.3s** | 若结果缓存命中，仅需中控 2.4s |

## **三、落地优先级建议**

### **优先级原则**

**#0 模型替换 > #1 / #2 / #3 / #4 ****>****  #5**

#0 是收益最大的单项优化（-1s ~ -2s），且不改变 Agent 架构，应最优先推进；其余优化项在 #0 完成的基础上依次叠加。

---

### **效果不下降前提下的分级优化路径**

#### **P0 — 模型替换（收益最大，最高优先）**

| **优化项** | **关键动作** | **预期收益** | **验证条件** |
| --- | --- | --- | --- |
| **#0 非计算类模型**（已完成） | 维持 Doubao-Seed-2.0-lite-TPM | 已落地 | — |
| **#0 计算类模型替换** | Qwen3-Max（4.4s）→ Doubao-Seed-2.0-lite-TPM（2.5s），占比 23% | **-0.5s ~ -1.0s**（加权） | 离线评测计算类准确率 delta ≤ 1% |

> **P0 完成后端到端预期**：4.3s → **~3.3s ~ 3.8s**

---

#### **P1 — 工程优化（零/低风险，P0 完成后并行推进）**

| **优化项** | **关键动作** | **预期收益** | **效果风险** |
| --- | --- | --- | --- |
| **#3 KV 前缀缓存** | tpm上启用火山显式缓存（+8% TTFT） | **-0.1s ~ -0.2s** | 无（不改变输出） |
| **#3 Prompt 精简** | 去除冗余 few-shot 示例，压缩 system prompt | **-0.1s ~ -0.2s** | 低（不改变推理逻辑） |
| **#4 提前搜索** | 用户输入阶段预判意图，并发发起检索 | **-0.1s ~ -0.2s** | 无（只影响时序） |
| **#1 检索源优化** | 截断慢源（百度 1.2s），仅保留火山（766ms） | **-0.2s ~ -0.5s** | 需验证：火山单源覆盖率 gap ≤ 3% |
| **#2 检索剪枝** | query 改写数 N → 1~2；召回 top-6 → top-3 | **-0.1s ~ -0.2s** | 需验证：Recall@3 ≥ 95% Recall@6 |

> **P0 + P1 叠加后端到端预期**：~3.3s ~ 3.8s →  3s** ~ 3.3 s**

---

#### **P2 — 中长期，依赖基础设施或外部协同**

| **优化项** | **关键动作** | **预期收益** | **前置条件** |
| --- | --- | --- | --- |
| **#5 答案缓存** | 高频 / 语义相似 query 命中缓存直接返回 | **-1s ~ -2s**（命中时） | 需建设语义缓存层；实时性 query 需排除；命中率 ≥ 20% 才有显著均值收益 |

> **P0 + P1 + P2 叠加后端到端预期（10% 命中率估算）**：**~ 2.4s ~ 3.3s**
