    prompt: "Extract all new features, APIs and breaking changes"
  })
← 返回 Haiku 提取的详细内容
```

**第 3 轮——回答**：主模型综合搜索摘要和详细页面内容，生成带引用的完整回答

### 4.3 模型何时决定深入获取

这完全是模型的自主推理，但通常受以下因素影响：

| 倾向调用 WebFetch | 倾向直接回答 |
| --- | --- |
| 搜索摘要太简略，信息不足 | 搜索摘要已足够详细 |
| 用户需要深入技术细节 | 用户只需概览 |
| URL 来自权威文档站（如 react.dev、docs.python.org） | URL 来自新闻聚合站 |
| 上下文窗口余量充足 | 接近上下文上限 |

---

## 5. 总结

| 维度 | WebSearch | WebFetch |
| --- | --- | --- |
| 用途 | 搜索未知信息 | 获取已知 URL 内容 |
| 执行位置 | Anthropic 服务端 | 客户端本地 |
| 二次处理 | 服务端子模型消化搜索结果 | 客户端调 Haiku 摘要 |
| 权限粒度 | 工具整体级别 | 按域名，有预批准列表 |
| 缓存 | 无 | 15 分钟 LRU |
| 协作方式 | 提供 URL → 模型自主决定是否调 WebFetch | 接收 URL → 抓取详细内容 |

Claude Code 的联网信息获取是一个**两阶段模式**：WebSearch 负责"发现"（找到什么信息在哪里），WebFetch 负责"深入"（获取具体内容）。两者的衔接完全依赖模型在 agentic loop 中的自主推理，没有硬编码的管道——这也体现了 Claude Code 作为 AI Agent 的核心设计哲学：**让模型自主决策工具的使用方式和组合顺序**。
