# 背景—>为什么做中控3.0反思

中控3.0目标：中控3.0采用新的Agent范式架构，从之前的workflow切换到Agentic范式，目的是提升小v在多轮和复杂场景的决策准确率，提升小v整体的智能化水平，提升用户体验

**反思的必要性：中控3.0从预研到最终落地，前后半年多，中间涉及很多的问题，包括效果问题，链路联调问题以及项目协作对齐等问题，本文主要对过去半年的3.0工作进行总结，为大家全面呈现其中的问题，希望在后续中控3.0大规模落地过程中，避免类似问题发生，提升改造效率，加速中控3.0全面落地。**

## 中控2.0存在效果问题

中控2.0包括改写、工具检索、意图识别、fc等模块，其采用的是workflow设计方式，本质是让用户的query按照预先设计的流程经过各个模块完成处理，生成最终执行结果反馈给用户；其优点是整体可控且在大多数场景可以满足用户；但是在复杂场景或者在一些多轮场景，效果并不理想，下面是一些线上反馈的不智能问题：

## 中控3.0的Agent架构

基于中控2.0的效果问题以及大模型Agent能力发展和行业趋势，我们在8月份提出将workflow改成中控3.0的Agent架构，中控3.0的目标是端到端的让模型自主决策；**如果说中控2.0利用大模型的方式是将大模型放在固定的模块中做意图识别和提槽工作，就像把大模型放在笼子里做决策；中控3.0则提供充分且完备的上下文信息(接收技能执行结果反馈，即技能支持反查)并且采用React方式让模型自主决策(所有回复统一模型生成)**，下面是中控3.0的架构示意图：
