具备推理能力的“决策者”，先推理再选择 Agent 集合。该设计将路由从传统的黑箱分类任
务转变为透明且可解释的推理过程，使系统能够明确说明何时以及为何多个 Agent 可能适用。
除了 Agent 选择机制外，还引入了一种新的协作执行流程。每个被选中的专家 Agent 先生成
一个该领域特定的结果，然后再由 RefiningAgent 汇总并整理这些输出，形成逻辑连贯的最
终结果。

## 1、算法流程

1）Reason-then-Select
TCAR 在输出 Agent 之前，会先生成一段自然语言推理链，明确说明问题可能涉及哪些
技术栈，不同 Agent 的职责边界，为什么多个 Agent 执行是合理的，这让路由不再是黑盒，
而是可解释、可 Debug、可持续优化 Agent 描述。
2）多 agent 共同输出
在 TCAR 中路由结果不再是 one-hot 单一分类，而是一个 Agent 子集，这一步主要解决
了实际应用场景中最棘手的 Agent 冲突问题（在小 v 助手中，通常通过规则定义强行将某一
类话术/query 定义到某个工具中，来解决冲突问题。如记录身高体重，可以是速记，也可
能是个人卡证信息记忆，存在模糊冲突地带）：不强行压缩决策，而是保留不确定性，交给
后续协作解决。当然这需要建立在对指令聪明且充分的理解力上。
传统的任务路由通常每个 query 只能分配给一个 Agent。这种方案隐含假设了严格且互
斥的领域边界，以及明确定义的意图空间，这些假设在真实企业环境中很少成立。当多个
Agent 因域职责重叠或跨域问题特性同时适合处理 query 时，会发生 Agent 冲突。
3）RefiningAgent 整合结果
当 TCAR 选出多个候选 Agent 后，每个 Agent 会独立给出自己的专业答案，而后由一个
RefiningAgent 负责对比、消歧、融合，最终输出一个完整、无冲突的答案，这套模式在排
障类问题上效果尤其明显。

## 2、算法特点

1）可扩展性：TCAR 支持动态添加新智能体，无需重新训练模型。新智能体只需添加其
描述即可，提高了系统可扩展性和业务适应性。
2）协作执行：通过引入“多智能体生成和总结”模式，TCAR 能够缓解智能体冲突，利
用多个智能体的专业知识，能生成更全面和可靠的最终回答。
3）系统效率和成本：在复杂场景下，多个智能体的调用可能增加系统的总体成本和延
迟。

具体步骤：
1）输入：用户 query、context 上下文信息（历史路由结果、手机状态、历史工具等）、
候选工具集（包括工具名、描述定义、参数列表）；
2）相似 query 召回：从 query 库中召回相似 query、对应相似度；
3）路由模型分类：大模型根据 query、context 上下文信息（历史路由结果、手机状态、
历史工具等）、向量召回结果，输出分类结果（可以考虑输出二级更细的类别）、原因以及
置信度（后续对于置信度低的 query，直接打判到 pro 模型）；
4）综合判断输出：根据模型分类结果和相似 query 召回结果（大于一定阈值直接采信
相似 query 对应的类别），综合判定 query 意图类别（简单意图、复杂意图）

## 3、方案说明

1）模型选择：如果需要做的准，至少需要 14B-30B 的模型，智能路由模型需要综合 query、
上下文信息、候选工具信息，进行判断推理，模型能力要求较高，7B 的小模型很难完成任
务。
2）标签体系：路由模型输出的标签体系需要更多根据 query 自身特点来定（维度比较
稳定，但类别比较复杂繁多），而不仅仅是模型能力大小去定（模型能力会随着模型迭代快
速变化），所以路由的标签体系足够的细，可扩展性强，而不是简单的二分类。否则后续如
果能力有变动，简单的二分类可能就不再适应用户需求。
