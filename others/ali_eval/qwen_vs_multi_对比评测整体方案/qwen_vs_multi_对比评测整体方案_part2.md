> **为什么输出多维度而非仅总分**：一个"1 分"可能掩盖不同问题——是事实错误还是遗漏？多维度能精确定位方案的强弱项，且不增加额外 LLM 调用成本（同一次调用输出更丰富的 JSON）。

**Judge 输出格式**（更新 `judge.py` 的 prompt）：

```json
{
  "overall": 2,
  "accuracy": 2,
  "completeness": 1,
  "relevance": 2,
  "remark": "答案准确且相关，但遗漏了薪资范围这一用户隐含关注点"
}
```

#### 3.2.2 指标定义（全部使用原始值，不做 min-max 归一化）

##### A. 核心质量指标（从 `overall` 评分派生）

| 编号 | 指标 | 方向 | 计算方式 | 说明 |
|------|------|:--:|---------|------|
| 5.1a | 满意率 | ↑ | `N_overall=2 / N_total` | 完全正确的 query 占比 |
| 5.1b | 不满意率 | ↓ | `N_overall=0 / N_total` | 完全翻车的 query 占比 |
| 5.2 | 加权平均分 | ↑ | `(2×N₂ + 1×N₁ + 0×N₀) / N_total` | 综合标量，范围 0~2 |

##### B. 对比指标（核心指标，直观且公平）

| 编号 | 指标 | 方向 | 计算方式 | 说明 |
|------|------|:--:|---------|------|
| 5.3a | **胜率** | ↑ | `N_win / N_total` | 同 query 下 `overall` 更高的 query 占比。**直接回答"哪个方案更好？"** |
| 5.3b | 平局率 | — | `N_tie / N_total` | 两方案 `overall` 相同的 query 占比 |
| 5.3c | 败率 | ↓ | `N_loss / N_total` | 同 query 下 `overall` 更低的 query 占比 |

> **胜率为什么重要**：满意率是"绝对值"，胜率是"相对值"。两方案满意率可能接近（如 0.65 vs 0.62），但胜率可能揭示"在大多数 query 上谁更好"。胜率 + 满意率合看，才能完整判断优劣。

##### C. 分维度指标（从 `accuracy` / `completeness` / `relevance` 派生）

| 编号 | 指标 | 方向 | 计算方式 | 说明 |
|------|------|:--:|---------|------|
| 5.4a | 事实准确率 | ↑ | `mean(accuracy) / 2` | 归一化到 0~1，越高越准确 |
| 5.4b | 完整度得分 | ↑ | `mean(completeness) / 2` | 归一化到 0~1，越高越完整 |
| 5.4c | 相关性得分 | ↑ | `mean(relevance) / 2` | 归一化到 0~1，越高越相关 |

> **分维度指标的价值**：定位"差在哪"。例如 qwen3.6-agent 可能相关性高但事实准确率低（编造），多引擎路由可能事实准确但遗漏信息。

##### D. 辅助指标

| 编号 | 指标 | 方向 | 计算方式 | 说明 |
|------|------|:--:|---------|------|
| 5.5 | 单轮可用率 | ↑ | `N_answer_not_empty / N_total` | 第一轮产出可见答案的 query 占比。排除确认卡/追问/索要上下文等中间态 |
| 5.6 | 溯源覆盖率 | ↑ | `count(attribution_score ≥ 0.5) / N_total_refs` | 仅多引擎路由可用。qwen3.6-agent 无结构化引用，此项为 N/A |
| 5.7 | 平均答案长度 | — | `mean(len(answer))` | 仅作参考，不纳入指标对比。用于判断是否有长度偏差 |

##### E. 指标使用决策（供选择）

| 指标 | 建议 | 理由 |
|------|:---:|------|
| 5.1a 满意率 | ✅ 必选 | 最直观的质量指标 |
| 5.1b 不满意率 | ✅ 必选 | 底线指标，惩罚翻车方案 |
| 5.2 加权平均分 | ✅ 必选 | 单一标量，方便排名 |
| 5.3a 胜率 | ✅ 推荐 | 回答"谁更好"的最直接指标 |
| 5.3b 平局率 | ⚪ 可选 | 辅助解读胜率 |
| 5.4a 事实准确率 | ✅ 推荐 | 定位"编造"问题 |
| 5.4b 完整度得分 | ✅ 推荐 | 定位"遗漏"问题 |
| 5.4c 相关性得分 | ⚪ 可选 | 定位"偏题"问题 |
| 5.5 单轮可用率 | ✅ 必选 | 排除无法评测的 query |
| 5.6 溯源覆盖率 | ✅ 推荐 | 多引擎路由独有优势，体现可追溯性差异 |
| 5.7 平均答案长度 | ⚪ 参考 | 不纳入指标对比，仅用于解释长度偏差 |

#### 3.2.3 分场景分析

所有核心指标（5.1~5.4）按以下维度分组统计：

```
按 category:  resume_opt vs interview_prep
按 industry:  10 个行业
按 complexity: single / multi / incremental
按 company:   高频公司
按 position:  高频岗位
```

- **不纳入指标对比**，只做分组柱状图/热力图展示
- **意义**：发现"某方案在某类问题上特别强/弱"的局部信号

### 3.3 D6 性能与鲁棒性

#### 3.3.1 指标定义

| 编号 | 指标 | 方向 | 计算方式 | 权重 |
|------|------|:--:|---------|:---:|
| 6.1 | API 调用成功率 | + | `N_success / N_total` | 0.20 |
| 6.2 | 超时率 | - | `N_timeout / N_total` | 0.10 |
| 6.3a | 端到端耗时 P50 | - | `percentile(elapsed_ms, 0.50)` | 0.15 |
| 6.3b | 端到端耗时 P95 | - | `percentile(elapsed_ms, 0.95)` | 0.15 |
| 6.3e | 端到端耗时 P99 | - | `percentile(elapsed_ms, 0.99)` | 0.10 |
| 6.3c | 服务端耗时中位数 | - | `percentile(server_ms, 0.50)` | 0.15 |
| 6.4 | 耗时标准差 | - | `stdev(elapsed_ms)` | 0.10 |
| 6.3d | 网络耗时占比 | - | `mean(network_ms / elapsed_ms)` | 0.05 |

#### 3.3.2 耗时采集方法

**多引擎路由**（直接调用内部函数，不走 HTTP）：
```python
t0 = time.time()
# Step 1: 多引擎搜索 + RRF 融合
search_results = search(intent="通用", query=query, timeout=6.0)
search_ms = (time.time() - t0) * 1000

# Step 2: LLM 基于搜索结果生成答案
t_llm0 = time.time()
answer = llm.invoke(prompt)  # Doubao-Seed-2.0-lite
llm_ms = (time.time() - t_llm0) * 1000

elapsed_ms = (time.time() - t0) * 1000
server_ms = search_ms + llm_ms   # 搜索 + LLM 耗时
network_ms = None                 # 直接调用无网络拆分
```

**qwen3.6-agent**（SSE 流式 API）：
```python
t0 = time.time()
result = call_qwen_agent(query)  # SSE 流式
elapsed_ms = (time.time() - t0) * 1000
# server_ms 无法精确拆分（SSE 流式），标记为 None
```

### 3.4 指标对比方案

#### 3.4.1 不做归一化，直接使用原始值

**2 方案对比不需要 min-max 归一化**。归一化会把微小差异极端化为 0 vs 100（如满意率 0.65 vs 0.58 → 100 vs 0），结论失真。

**正确做法**：报告中直接展示原始值，配合统计显著性检验（Mann-Whitney U / Wilcoxon）和效应量（Cohen's d / Cliff's delta）判断差异是否真实。

#### 3.4.2 核心对比维度

| 维度 | 核心指标 | 说明 |
|------|---------|------|
| **D5 答案质量** | 满意率、不满意率、加权平均分、胜率、事实准确率、完整度得分 | 直接对比原始值 |
| **D6 性能** | 成功率、超时率、P50/P95 耗时、耗时标准差 | 直接对比原始值 |
| **D5 溯源** | 溯源覆盖率 | 仅多引擎路由可用，单独标注 |
| **D5 可用性** | 单轮可用率 | 排除无法评测的 query |

#### 3.4.4 结论判定规则

不使用 S/A/B/C/D 等级（需要归一化），改为：
