## 一、背景与目标

### 1.1 被测对象

| 方案代号 | 说明 | 搜索机制 |
|---------|------|---------|
| **qwen3.6-agent** | 使用 qwen3.6 模型内置的搜索能力，Agent 自行决定是否搜索、搜什么、搜几次 | 模型自主决策，黑盒搜索 |
| **多引擎路由** | 当前项目 search_agent 的搜索架构：通过 `search_engines.search()` 调用搜索引擎，RRF 融合后传给 LLM 生成答案 | 多引擎搜索 + RRF 融合 + LLM 总结 |

### 1.2 对比目标

回答以下核心问题：

1. **质量**：qwen3.6-agent 的自主搜索能力，能否达到甚至超越多引擎路由的答案质量？
2. **性能**：qwen3.6-agent 的端到端延迟和稳定性，是否满足上线要求？
3. **场景差异**：在简历优化和面试准备两个场景下，两套方案的优劣势分别是什么？
4. **行业差异**：不同行业（互联网/金融/汽车/医疗等）下，哪套方案表现更好？
5. **可追溯性**：多引擎路由能否提供更好的答案溯源能力？

### 1.3 评测约束

- **单轮评测**：每条 query 发送后只取第一轮回复作为评测对象。query 必须确保单轮内产出可见的搜索结果内容，而非确认卡/追问/设置收集等中间态。
- **不涉及 D1~D4**：qwen3.6-agent 返回的是纯文本，无法获取结构化搜索结果（召回量、RankScore、时效性、URL 多样性等），因此仅对比 D5（答案质量）和 D6（性能与鲁棒性）。

### 3.2 D5 端到端答案质量

#### 3.2.1 单条评分标准

每条 query 的答案由 LLM Judge 打分，输出**多维度评分**（非仅 0/1/2 总分）：

| 维度 | 分值 | 含义 |
|------|:---:|------|
| `overall` | 0 / 1 / 2 | **综合评分**：0=不满意，1=瑕疵，2=满意 |
| `accuracy` | 0 / 1 / 2 | **事实准确性**：答案中的数据、事实是否准确，有无编造 |
| `completeness` | 0 / 1 / 2 | **覆盖完整度**：是否覆盖了 query 的所有核心子问题 |
| `relevance` | 0 / 1 / 2 | **相关性**：答案是否紧扣 query，有无偏题、答非所问 |

> **为什么用 0/1/2 而非 1~10**：0/1/2 粒度刚好（不行/还行/好），评判标准一致性好，业务含义清晰。比 1~10 分更容易在不同 query 间保持标准一致。参考 LMSYS Chatbot Arena（1~5）和本项目现有 task A（0/1/2）的实践。
