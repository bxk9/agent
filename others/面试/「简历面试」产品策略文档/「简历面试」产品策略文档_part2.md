| **输出** | **结构化 JD + 多维公司画像【前置总结】**：<br>- JD 结构化字段（职责/硬技能/软技能/门槛/隐性偏好）<br>- 公司基底（7 维：行业/规模/阶段/业务/技术栈/价值观/战略）<br>- 岗位人才偏好（3 维：团队定位/岗位重心/晋升路径）<br>- 数据来源标注（每个字段标注来源 URL/文档） |

### ② 简历解析与对齐诊断

| 维度 | 详细说明 |
| --- | --- |
| **输入** | 1. **用户简历**：PDF / Word / 图片 / 文本，端侧 OCR + 解析<br>2. **目标 JD**：来自能力①的结构化 JD<br>3. **公司画像**：来自能力①的公司基底+岗位调味<br>4. **优秀简历样例**：行业/岗位匹配的脱敏样例（来自合作样本库）<br>5. **用户求职记忆**：记忆中过往简历版本与投递反馈 |
| **处理逻辑** | 1. **简历结构化**：抽取基本信息/教育/工作经历/项目/技能/获奖等模块，每条工作/项目拆为 STAR 结构（情境/任务/行动/结果）<br>2. **对齐分析**：将简历每条 bullet 与 JD 的硬技能/软技能/职责清单做语义对齐<br>3. **优秀样例对标**：检索同岗位优秀样例的表述方式与重点分布<br>4. **结合公司、岗位偏好，进行个性化四象限诊断**：　<br>- ✅ **匹配项**：简历有 + JD 要 → 提示加强突出　<br>- ⚠️ **漏项**：JD 要 + 简历没 → 提示是否真的没有 / 怎么补　<br>- 🔵 **弱项**：有但表述弱 → 提示如何改写　<br>- 🚫 **风险项**：与 JD 偏好相悖（如 JD 要稳定、简历跳槽频繁）→ 提示如何弱化或正面回应 |
| **输出** | **结合公司、岗位偏好，输出个性化诊断报告**：<br>- 简历结构化数据（JSON）<br>- 四象限诊断清单（每项含：原始 bullet / 对齐结论 / 改进建议 / 依据来源）<br>- 整体匹配度概览（匹配项数 / 漏项数 / 弱项数 / 风险项数，不打分）<br>- 改写优先级建议（按"对求职结果影响度"排序） |

### ③ 简历定向生成/改写与渲染

> 生成简历时，若用户未指定沿用原简历版式，则基于优质简历库自动优化排版。

| 维度 | 详细说明 |
| --- | --- |
| **输入** | 1.用户求职信息、经历<br>2.能力②输出的对齐诊断报告<br>3. 用户对每条建议的采纳决策（接受/拒绝/我来改）<br>4. JD 与公司画像（保持上下文一致）<br>5. 用户原简历的版式/排版偏好（来自记忆） |
| **处理逻辑** | 1.**简历生成：**基于用户输入的信息、记忆、通用模版，生成简历<br>2.**单条 bullet 改写**（`resume.rewrite_bullet`）：保留事实、增强 STAR 完整度、对齐 JD 用词、保留个人语气<br>3. **整体编排**（`resume.tailor_compose`）：调整模块顺序、突出与 JD 强相关的项目/技能、压缩弱相关内容、控制总篇幅<br>4. **Diff 渲染**（`resume.diff_render`）：原版 vs 改写版逐行对照，高亮变更<br>5. **可下载渲染**（`resume.render` + `file.save_to_local`）：渲染为 PDF / DOCX，端侧保存到用户设备<br>6. **版本沉淀**：每个 JD 对应一份定制版，沉淀到记忆 |
| **输出** | - 生成、改写后简历的结构化数据<br>- Diff 视图（HTML / 内置渲染）——pc claw<br>- 定制版简历文件（PDF/DOCX）+ 本地保存路径<br>- 简历版本 ID（关联本次 JD，可后续查阅 / 进入面试模拟时自动加载）<br>-1、当用户的query里面涉及到简历-‘公司’-'岗位'以及版本’内容——则按 【简历-‘公司’-'岗位'-‘时间’】进行命名<br>2、什么用户query中没有提到公司或岗位——沿用用户原文件名+时间戳 |
