## 〇·五、端云协作架构说明

> 本章说明端云双层协作的具体机制，是本次架构升级的核心新增内容，供各承接团队理解调用边界。

### 分工原则

| 维度 | 手机端侧 Claw | 云侧 Claw（Law） |
| --- | --- | --- |
| **执行环境** | Android 系统；受限算力；移动网络 | 电脑浏览器环境；充足算力；稳定网络 |
| **核心职责** | 用户 UI 交互、意图识别、Skill 编排、系统感知（通知/日历/录音）、本地存储 | 浏览器自动化（三方平台）、重量级 ASR、文档渲染（PDF/DOCX）、长 context LLM 任务 |
| **数据持久化** | 本地 Room DB + 加密文件系统（不上云） | 任务执行过程临时数据；结果回传后不留存 |
| **触发方式** | 主动；用户直接交互 | 被动；由端侧 Claw 调起 |
| **不可替代场景** | Android ContentProvider（通知/日历/录音文件访问） | 三方平台浏览器访问、重量级 ASR、PDF/DOCX 渲染 |

### 端云调起协议（Skill 层抽象）

端侧 Claw 通过标准 Skill 调用透明触发云侧任务，**各承接团队不需要感知端云通信细节**，只需在 Skill 定义中标注 `execution_target`:

```json
{
  "name": "audio.asr_batch",
  "type": "skill",
  "execution_target": "cloud",          // "local" | "cloud" | "adaptive"
  "description": "对通话录音文件进行 ASR 转写和说话人分离...",
  "parameters": {
    "recording_path": "string",
    "channel_mode": "mono | dual"
  },
  "returns": {
    "transcript": "array of {speaker_id, text, start_ms, end_ms}"
  }
}
```

| `execution_target` 值 | 含义 |
| --- | --- |
| `local` | 仅端侧执行（如 notify.capture、calendar.write） |
| `cloud` | 必须云侧执行（如 audio.asr_batch、resume.render、browser.automation） |
| `adaptive` | 缓存命中走端侧，未命中时调起云侧（如 search.dispatcher 中的三方平台查询） |

### 降级策略

```plaintext
云侧 Claw 可达？
    │
    ├─ YES → 正常执行，结果回传端侧
    │
    └─ NO（网络断开 / 云侧繁忙 / 登录态失效）
           │
           ├─ search.*     → 降级到 Web Search 兜底（结果质量下降，告知用户）
           ├─ audio.asr    → 提示用户稍后重试，面试录音文件本地保留
           ├─ resume.render→ 降级输出 Markdown 格式（端侧直接渲染）
           └─ browser.*   → 提示用户手动粘贴内容，走 TextAdapter 处理
```

## 一、技术汇总大表

> **架构前提**：本方案基于 Open Claw 框架，采用**端云双层协作**架构。Skill = 原子能力，Workflow = 编排剧本，主模型（手机端龙虾大脑）通过读取 **Skill 定义** 决定何时调用哪个 Skill/Workflow，重计算/浏览器访问任务通过端云通信调起云侧 Claw（Law）执行，**不需要单独构建意图分类器**。算法团队的职责是实现 Skill 内部逻辑 + 写好 Skill 触发描述。
> 承接方说明：**文档问答相关**（文本理解/生成/评估）、**图片问答相关**（图像OCR/视觉理解）、**记忆相关**（跨session持久化/调度）、**云侧 Claw**（浏览器自动化/重量级ASR/文档渲染，端云协作新增层）。原先标注 `⚠️ 待定` 的三方平台接入/ASR/渲染，在端云协作架构下均由**云侧 Claw** 承接，不再待定。

| 编号 | 场景 | 技术点 / Skill | 任务类型 | 核心风险 | 技术承接方 | 关键参数 |
| --- | --- | --- | --- | --- | --- | --- |
| 0-0 | 通用前置 | **Skill 定义设计** | Skill 触发描述编写 | 描述不准确导致主模型漏/误触发 | 各团队各自负责 | `name`, `description`(触发条件), `parameters`(schema) — **与主模型共享** |
