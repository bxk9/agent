| **关键约束** | "风格"是模糊概念，LLM 提炼结果一致性差；**第一期建议人工预定义主流公司×岗位的风格模板作为兜底**，搜索检索作为补充 |

### 技术点 1-4：经历改写 · `resume.rewrite_bullet`

| 项 | 内容 |
| --- | --- |
| **任务类型** | 受限文本生成（Constrained Generation） |
| **输入** | 原始 bullet 文本 + **JD 结构化要求（显性+隐性需求）** + **公司特性画像** + **小红书/Web 简历参考样本**（经 search.dispatcher 检索）+ memory 中该 bullet 历史表现 |

### 技术点 2-4：模拟面试 · `interview.session_context`（主模型扮演面试官）

> 在 Open Claw 框架下，**不需要另建面试官 Agent**。主模型本身就是 Agent，`interview.session_context` 是一个 Skill，被调用后将公司画像注入 session 上下文，主模型随即按画像定义的风格扮演面试官角色，整个多轮问答都由主模型驱动。

**前置步骤：面经搜索驱动的题目优先级排列**

模拟面试开始前，先通过 `search.dispatcher` 检索该公司+岗位的真实面经，提取高频题目，与 JD 分析和 memory 弱项共同决定出题顺序：

```plaintext
search.dispatcher(type=interview_exp, source=[小红书,牛客,看准], company, role)
        │
        ▼
面经解析：提取各题目出现频次 → 生成 question_frequency_map
        │
        ▼
题目优先级排列（三维加权）：
  ① 面经频率分（这道题在真实面试中出现次数多）
  ② JD 对齐分（JD 显性要求直接对应的题目）
  ③ memory 弱项加权（用户历史答差过的维度优先练）
        │
        ▼
生成有序题库（高优先级题前置），存入 memory.job_journey
```

| 项 | 内容 |
| --- | --- |
| **任务类型** | 面经搜索 + 频率统计 + 多维排序 + session 上下文注入 |
| **输入** | 公司+岗位（触发面经搜索）+ JD 结构化结果 + memory 历史弱项 + 用户每轮作答 |
| **输出** | 按优先级排序的题库（持久化到 memory）+ 当场动态追问（主模型扮演面试官） |
| **技术方案** | 面经搜索 → 频率统计 → 三维加权排题 → 注入 session；主模型按题库顺序出题，追问≤3层；**题库持久化存入 **`**memory.job_journey**`**，用户下次练习可继续上次进度或重置重练** |
| **关键约束** | 面经搜索到高频题与 JD 无关时（如某公司面试喜欢问"你最大的缺点"）需要纳入而不过滤；题库存储要区分"已练过"和"未练过"，避免用户重复刷同一题；面经 TTL=7天，面经更新后题库需主动失效重建 |

### 技术点 2-5：对齐式即时反馈 · `answer.alignment_check`

| 项 | 内容 |
| --- | --- |
| **任务类型** | 基于 rubric 的文本评估（不打分） |
| **输入** | 用户作答 + 本场绑定的公司画像（固定 rubric） |
| **输出** | `{aligned_points[], misaligned_points[], improvement_direction}` |
| **技术方案** | LLM 以公司画像为 rubric 逐维度判断：字节看 ownership/量化，腾讯看协同/稳重；**内部产生轻量严重程度分（0-2）** 用于后续 memory 写入和题库加权，**对用户只展示文字反馈** |
