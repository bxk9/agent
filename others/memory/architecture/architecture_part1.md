## 1. 系统总览

### 1.1 设计理念

人类对话依赖三种记忆协同：

| 记忆类型 | 人类类比 | 时间跨度 | 系统对应 |
|---------|---------|---------|---------| 
| 工作记忆 | 当前正在想的事 | 秒级 | L1: 滑动窗口原文 |
| 情景记忆 | 对某次事件的回忆 | 分钟~天 | L2: 场景级摘要 |
| 长期记忆 | 对一个人的稳定认知 | 天~年 | L3: 用户画像 KV |

## 2. 完整数据流

### 2.1 一条消息的 13 步处理链

```
Step 1:  用户发送消息 user_msg
            │
Step 2:  [预处理] 情感检测
            │     输出: emotion_label (类型/强度/变化趋势)
            │
Step 3:  [预处理] 意图识别
            │     输出: intent_tree (L1->L2->L3->L4->L5)
            │             + is_scene_switch 标记
            │
Step 4:  [记忆管理] L1 工作记忆更新
            │     将当前轮追加到滑动窗口，淘汰超窗口的旧轮
            │
Step 5:  [记忆管理] 场景管理
            │     基于 Step3 的 is_scene_switch 判断：
            │     ├─ 新建场景 / 恢复旧场景 / 维持当前场景
            │     └─ 若切换: 对旧场景执行剩余轮强制压缩
            │
Step 6:  [记忆管理] L2 压缩检查
            │     当前场景未压缩轮数 >= 10 ?
            │     ├─ 是: 取 10 轮 -> LLM 压缩 -> 写入场景文件
            │     └─ 否: 跳过
            │
Step 7:  [记忆管理] L3 更新检查
            │     从 user_msg 中检测是否有新的用户画像信息
            │     ├─ 有: 提取 KV -> 冲突检测 -> merge 到 L3
            │     └─ 无: 跳过
            │
Step 8:  [记忆召回] 从 L2/L3 检索相关记忆
            │     输入: intent + emotion + user_msg
            │     输出: recalled_memories[] (带相关性分数)
            │
Step 9:  [软阈值] 计算"记忆提及必要性"分数
            │     ├─ >= 0.85 (硬阈值): 强制���入
            │     ├─ >= 0.60 (软阈值): 建议注入
            │     └─ < 0.60: 不注入
            │
Step 10: [Prompt组装] 动态拼接 System Prompt
            │     Block1: 角色设定 (固定)
            │     Block2: L3 长期记忆 (动态)
            │     Block3: L2 场景摘要 (动态, 受 Step9 控制)
            │     Block4: 情感状态 (动态)
            │     Block5: 记忆提及指引 (动态, 受 Step9 控制)
            │     Block6: 回复策略 (动态)
            │     + Messages: L1 工作记忆原文
            │
Step 11: [LLM推理] 发送请求, 获取 response
            │
Step 12: [后处理] 从 (user_msg, response) 提取新记忆
            │     可能触发 L3 更新 (补充 Step7 未检测到的)
            │
Step 13: [后处理] 更新情感序列窗口
            │     返回 response 给用户
```

### 2.2 步骤依赖关系图

```
           ┌──── Step2 (情感) ────┐
           │                      │
Step1 ─────┤                      ├──── Step4 ──── Step5 ──── Step6
(输入)     │                      │                             │
           └──── Step3 (意图) ────┘                     Step7 ──┤
                                                                │
Step13 ◄── Step12 ◄── Step11 ◄── Step10 ◄── Step9 ◄── Step8 ◄──┘
```

关键并行点:
- Step2 / Step3 可并行（都只依赖 Step1）
- Step6 / Step7 可并行（分别处理 L2 和 L3）
- Step5 依赖 Step3（需要意图来判断场景切换）

## 3. 预处理层

> 详细设计: [intent_classification.md](./intent_classification.md)

### 3.1 情感检测模块

**输入**: user_msg + 最近 3 轮历史  
**输出**:

```json
{
    "primary": "frustrated",
    "intensity": 0.75,
    "valence": -0.6,
    "arousal": 0.7,
    "shift": "escalating",
    "confidence": 0.85
}
```

**检测优先级**:

| 优先级 | 信号源 | 示例 |
|--------|--------|------|
| P0 | 显式情感词 | "好开心""烦死了" |
| P1 | 标点/语气词 | "！！""呜呜""哈哈" |
| P2 | 上下文推理 | 结合前文推断隐含情绪 |
| P3 | 话题情感色彩 | 失恋/升职等话题自带色彩 |
