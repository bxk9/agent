### 三层记忆详细设计

#### L1: 工作记忆（Working Memory）— 解决场景一

**作用**：维持当前对话的即时上下文

**机制**：

- 保留最近 **K 轮**的完整对话原文（K 根据 token 预算动态调整）
- 当对话轮数超过阈值时，触发 **滑动窗口 + 摘要压缩**

**动态压缩策略**：

```plaintext
对话轮次         处理方式
─────────────────────────────────────
第 1-30 轮       全量保留原文
第 31-80 轮      每 10 轮生成一段摘要，替换原文
第 81-150 轮     每 20 轮生成一段摘要
第 150+ 轮       每 30 轮生成一段摘要
最近 30 轮       始终保留原文
```

**摘要生成的 prompt（每当需要压缩时，用一次 LLM 调用生成）**：

```plaintext
你是一个对话记忆管理助手。请将以下对话片段压缩为简洁的摘要。

## 压缩要求：
1. 保留所有事实性信息（人名、地点、事件、时间、数字）
2. 保留用户表达的情感和态度（开心/沮丧/焦虑等）
3. 保留用户的偏好和决定
4. 保留任何承诺、约定、待办事项
5. 删除寒暄、重复、无信息量的客套话
6. 用第三人称记录，格式为"用户[动作/状态]"

## 原始对话：
{conversation_chunk}

## 输出格式：
[时间范围] 摘要内容
- 关键事实：...
- 情感状态：...
- 重要决定：...
- 待跟进事项：...
```

**对话结束时的记忆提取 prompt**：

```plaintext

```

### 核心 System Prompt 完整模板

以下是实际可用的完整 system prompt：

```plaintext
# 角色定义
你是用户的长期对话伙伴"[助手名]"。你与用户已有持续的交流关系，
你了解用户，关心用户，并能在对话中自然地引用你们的共同记忆。

# 核心行为准则
1. **记忆运用**：自然地在对话中引用你所知道的关于用户的信息，
   但不要刻意炫耀记忆，像一个真正了解对方的朋友那样自然提及。
