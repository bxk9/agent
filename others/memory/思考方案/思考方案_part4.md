- 只在对当前话题有帮助时引用记忆，不无端提起
- 如果不确定某条记忆是否准确，用试探性语气："我记得你好像提过...对吗？"
- 永远不要说"根据我的记录"、"我的数据库显示"等机械化表达
```

**3. 渐进式记忆暴露**

不要在第一次跨对话时就一次性展示所有记忆，而是逐步在适当时机引用：

```plaintext
第二次对话：引用 1-2 条上次的关键信息
第三次对话：可以引用更多细节
第五次以后：可以引用较早期的记忆

这样用户会自然地感觉到"这个AI真的记住了我"，而不是突然感到"被监视"。
```

**4. 错误记忆的优雅处理**

```plaintext
## 记忆纠错规范
- 如果用户纠正了你的某条记忆，立即承认并更新
- 回应方式："啊对不起，我记混了，谢谢你纠正"
- 立即触发记忆更新流程
- 不要辩解或解释为什么记错了
```

## 实施成本和技术选型建议

### 存储方案

| 记忆层 | 存储方案 | 预估单用户存储 |
| --- | --- | --- |
| L1 工作记忆 | 内存/Redis（会话级） | 50-200 KB |
| L2 情景记忆 | PostgreSQL + pgvector | 1-10 MB |
| L3 长期记忆 | PostgreSQL | 10-100 KB |

### 额外 LLM 调用开销

| 操作 | 触发时机 | 额外 token 消耗 |
| --- | --- | --- |
| 对话压缩 | 每 10-30 轮 | ~2000 tokens/次 |
| 记忆提取 | 每次对话结束 | ~1500 tokens/次 |
| 话题识别 | 每次新对话开始 | ~500 tokens/次 |
| 情感检测 | 每轮 | ~200 tokens/次 |

### 向量嵌入模型推荐

- 中文场景：`bge-large-zh-v1.5`（北京智源）或 `text-embedding-3-small`（OpenAI）
- 维度：1024 或 1536
- 用于 L2 情景记忆的语义检索

## 方案总结

| 特性 | 本方案 | OpenAI Memory | Gemini 1M | Coze 三层 |
| --- | --- | --- | --- | --- |
| 场景一：200轮单对话 | ✅ 动态压缩 + 滑动窗口 | ⚠️ 依赖128K窗口 | ✅ 暴力全装 | ⚠️ 依赖底层模型 |
| 场景二：跨对话同话题 | ✅ 话题级情景记忆 | ✅ 自动记忆 | ❌ 较弱 | ✅ 数据库+向量 |
| 共情连续性 | ✅ 情感追踪子系统 | ⚠️ 无专门设计 | ❌ 无 | ⚠️ 依赖prompt |
| 记忆精准度 | ✅ 三层分级+冲突处理 | ⚠️ 扁平列表 | ❌ 无持久化 | ✅ 结构化 |
| 成本效率 | ✅ 动态压缩控制成本 | ✅ 低 | ❌ 极高 | ✅ 中等 |
| 用户体验 | ✅ 自然引用+渐进暴露 | ✅ 好 | ✅ 无感 | ⚠️ 需精心设计 |
| 实施复杂度 | ⚠️ 高（需完整后端） | ✅ 开箱即用 | ✅ 开箱即用 | ⚠️ 中等 |

**本方案的核心优势**：

1. **不依赖超长上下文窗口**，即使在 32K/128K 模型上也能工作
2. **不改变模型架构**，纯工程+prompt 实现
3. **情感追踪是独有的差异化设计**，其他厂商方案均未专门关注
4. **话题级记忆组织**是对扁平记忆列表的重要改进
5. **记忆引用的用户体验设计**确保功能不突兀
