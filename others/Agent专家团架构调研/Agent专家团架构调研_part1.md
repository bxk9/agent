##### 基础核心概念


##### Agent 的四个基本组成 + ReAct


##### 模式


##### Agent 的基本组成


##### 1


##### Persona（角色定义）

身份、职责、行为约束。通过 System Prompt 定义，决定了 Agent 的「性格」和「工作方式」。需要独立 System
Prompt → 大概率应该做成独立 Agent。

##### 2


##### Tools（工具集）

可调用的外部能力——文件读写、代码执行、搜索、API。遵循 MCP 标准接入。工具描述要明确、参数要简单、需要
标注是否有副作用。

##### 3


##### Memory（记忆）

短期：对话上下文（LLM 上下文窗口内）；长期：持久化知识和用户偏好（向量数据库/知识图谱）。决定了 Agent
能「记住」什么。

##### 4


##### Decision Loop（决策循环）

感知→思考→行动→观察，循环往复直至任务完成。基于 ReAct 模式，每步行动后观察结果再决定下一步，而非一次
性生成所有步骤。
ReAct 模式（Reasoning + Acting）：将「推理」和「行动」交替进行。大多数 Agent 基于此模式工作——每步行

##### 动后观察结果再决定下一步。

##### 两大关键协议 — MCP 与 A2A


##### MCP


##### Model Context Protocol


##### Agent → Tool

让 Agent 连接外部工具和数据源。标准化协议，避免为每个工具手写
connector。
基于 JSON-RPC 2.0 · 客户端-服务器架构 · 工具列表自动发现

##### A2A


##### Agent-to-Agent Protocol


##### Agent ↔ Agent

Google 提出的开放协议，让不同框架构建的 Agent 互相发现、通信和协
作。
JSON-RPC 2.0 over HTTP · Agent Card 自动发现

##### MCP 给 Agent 装上工具 | A2A 让 Agent 组成团队


##### Agent Card（A2A 自动发现）

每个 Specialist 在 /.well-known/agent-card.json 端点暴露能力声明：名称、
技能列表、输入输出格式、端点地址。
Orchestrator 通过 A2ACardResolver 并行获取所有 Agent Card → LLM
看完列表自主决定调谁、按什么顺序调。

##### A2A 协议栈

Agent Card → JSON-RPC 2.0 over HTTP →
message/send（发送消息）· tasks/get（查询任务）· tasks/cancel
（取消任务）→
Streaming (SSE) + Push Notifications + Multi-turn Context
A2A vs MCP 对比
A2A：Agent ↔ Agent 协作通信 | MCP：Agent → Tool/Resource 调用外部能力。
两者互补，不是替代。

##### CHAPTER 03 五层分层架构全景


##### 架构全景


##### 1


##### 用户层

系统的入口和出口。输入解析、意图识别，任务完成后将多 Agent 产生的结果整合为人类友好的格式返回。对话式
产品还需处理多轮对话上下文衔接。

##### 2编排层 最关键
核心层：任务分解→Agent 调度→上下文管理→流程控制→结果聚合。构建 DAG 依赖图，匹配 Agent，决定串行/
并行，处理重试/降级/终止。Agent 之间不直接通信，所有协调通过编排层。

##### 3
