## 1 项目概述

### 1.1 项目定位

`pro_agent` 是 **蓝心小V（Jovi）** 语音助手的 **3.0 Pro 中控服务**，作为用户意图与后端工具之间的智能编排层，承担以下核心职责：

- **意图理解与工具编排**：接收用户指令（含工具召回意图、上下文历史），通过 LLM 进行意图理解与工具选择
- **流式响应**：以 SSE（Server-Sent Events）流式协议向客户端下发文本、工具调用请求、会话状态
- **多轮对话管理**：支持多轮对话中的工具链式调用（串行/并行），维护会话状态
- **质量保障**：三阶段工具调用验证（规则/LLM/全局批量），确保工具调用准确性
- **运营干预**：彩蛋短路、Query Patch 注入、工具共现仲裁等运营能力
- **性能优化**：Context Pipeline 多级压缩、Responses API 缓存复用、Prompt Cache 优化

### 1.2 业务场景

pro_agent 服务于 vivo 手机的语音助手场景，典型用例包括：

- **工具调用**：「定一个早上八点的闹钟」→ 调用 `create_alarm` 工具
- **多轮对话**：用户追问「改成九点」→ 基于历史上下文调用 `modify_alarm`
- **知识问答**：「今天天气怎么样」→ 调用 `weather_query` 工具
- **闲聊模式**：「你好」→ 直接文本回复，不调用工具
- **运营彩蛋**：特定关键词触发特效或跳转

### 1.3 核心价值

1. **智能化**：通过 LLM 理解用户意图，自动选择合适工具
2. **可靠性**：三阶段验证框架，防止工具调用错误
3. **灵活性**：支持热更新配置、动态工具注入、运营干预
4. **高性能**：流式响应、缓存复用、上下文压缩，优化首字时间（TTFT）
5. **可扩展**：模块化设计，新工具接入成本低

## 2 架构演进历程

### 2.1 v1.0 - v2.0：单体架构

- **特点**：`HostAgent.process()` 为单体函数，承载所有业务逻辑
- **问题**：代码耦合度高、状态散落、难以测试和维护

### 2.2 v3.0 - v3.2：三阶段流水线

- **重构**：拆分为 `prepare → infer → finalize` 三阶段
- **收益**：职责清晰、可独立测试、状态收敛到 `TurnState`

### 2.3 v3.3：推理干预层

- **新增**：`hooks/` 推理干预层（PreInfer/PostInfer 两段式）
- **目的**：隔离主流程与场景化干预规则，支持定点干预

### 2.4 v4.0（当前）：流式管道与缓存优化

- **流式管道**：`StreamPipeline` 处理器链，统一处理模型输出
- **缓存优化**：Responses API 复用 KV Cache，减少重复计算
- **配置桥接**：声明式动态配置管理，支持热更新

### 3.1 架构总览

```
│                         客户端 / 语音助手                          │
└───────────────────────────────┬──────────────────────────────────┘

┌──────────────────────────────────────────────────────────────────┐
│                      FastAPI 入口层 main.py                        │
│   /stream/chat    /mock/chat    /setting/chat    /check.do        │
└────────┬────────────────────────────────────────────┬────────────┘
         │ AgentContext / body                       │ 工具意图检索
         ▼                                          ▼
┌──────────────────────────────────┐  ┌──────────────────────────┐
│   HostAgent（薄壳编排器）          │  │    意图检索服务            │
│   agent/pro/agent.py              │  │    (外部 HTTP 服务)       │
│   process() 串联三阶段流水线：      │  └──────────────────────────┘
│                                   │
│  ┌────────────────────────────┐  │   横切依赖：
│  │ _stage_prepare             │  │   • TurnState  单轮唯一真值

│  │  ·排序·工具结果后处理       │◄─┼── tools/mcp/post_process/ + PostInfer hooks
│  │  ·PreInfer hooks           │  │   • ModelSession 当前模型+切换
│  ├────────────────────────────┤  │   • RetryController 重试策略
│  │ _stage_infer               │  │   • hooks/ 推理干预层
│  │  构建 system_prompt·消息    │◄─┼── system.py + extra_prompts + 仲裁(arbitration)
│  │  ·流式推理·解析工具调用     │◄─┼── tools/mcp/pre_process/
│  │  ·工具验证(RETRY)·批量(DROP)│◄─┼── tools/validator.py + validators/
│  ├────────────────────────────┤  │
│  │ _stage_finalize            │  │

         ▼
┌──────────────────────────────────────────────────────────────────┐
│                         模型层 model/                              │
│   XuanjiModel (玄机协议)    │    Model (OpenAI 兼容协议)           │
│   ─ HMAC-SHA256 签名        │    ─ Bearer Token 认证              │
│   ─ 多协议适配              │    ─ 标准 function_calls             │
│   ─ 工具调用解析三层兜底     │                                     │
└──────────────────────────────────────────────────────────────────┘
         ▲                              ▲
         │                              │
┌────────┴──────────────────────────────┴──────────────────────────┐
│                    配置层 config/                                   │
│   ModelRegistry (type→model 映射)                                  │
│   ManagedConfigBridge (配置中心→子系统标准化适配)                    │
│   VivoConfigManager (30s 轮询远程配置中心)                          │
└──────────────────────────────────────────────────────────────────┘
```

### 3.2 核心设计原则

1. **单一职责**：每个模块只负责一个明确的职责边界
2. **依赖倒置**：高层模块不依赖低层模块，都依赖抽象
3. **开闭原则**：对扩展开放，对修改封闭（如 hooks、patches）
4. **状态收敛**：单轮状态收敛到 `TurnState`，避免散落局部变量
5. **安全降级**：任何环节异常时降级而非崩溃（验证器异常→PASS）

## 4 分层架构详解

### 4.1 入口层（main.py）

**职责**：HTTP 路由、请求参数校验、Agent 实例化

**核心端点**：

| 端点 | 说明 |
|---|---|
| `POST /stream/chat` | 生产入口，由上游中控分发工具召回结果后调用 |
| `POST /mock/chat` | 开发调试入口，自动调用意图检索服务后转发 |
| `POST /setting/chat` | 设置类请求入口，自动补充 `setting_result` |
| `GET /check.do` | 心跳检测 |

**初始化流程**：

```python
init_app()
    ├─ config_registry.init_all()          # 初始化所有配置桥接
    ├─ easter_egg_manager.start()          # 启动彩蛋规则轮询
    └─ init_arbitration()                  # 加载仲裁规则
```

### 4.2 Agent 层（agent/）

**职责**：单轮编排、三阶段流水线、状态管理

**核心组件**：

| 组件 | 文件 | 职责 |
|---|---|---|
| `HostAgent` | `agent/pro/agent.py` | 薄壳编排器，串联三阶段流水线 |
| `TurnState` | `agent/pro/turn_state.py` | 单轮唯一真值状态 |
| `ModelSession` | `agent/pro/model_session.py` | 当前模型 + 切换能力 |
| `RetryController` | `agent/pro/retry_controller.py` | 推理-校验循环的重试策略 |
| `StreamPipeline` | `agent/pro/stream/` | 流式处理器链 |
| `hooks/` | `agent/pro/hooks/` | 推理干预层（PreInfer/PostInfer） |

**三阶段流水线**：

| 阶段 | 模块 | 职责 |
|---|---|---|
| `_stage_prepare` | `stage_prepare.py` | 输入解析 → 工具集构建 → Patch/彩蛋/仲裁 → geocode → 工具结果后处理 |
