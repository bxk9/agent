ctx.chat_history = [msg for msg in ctx.chat_history if not is_stale(msg)]

# ❌ 整体替换对象（会被静默丢弃）
ctx.tool_call_response = ToolCallResponse(...)
```

**原理**：
- Context 与主流程共享同一对象引用
- 整体替换会创建新对象，主流程仍持有旧引用
- 原地修改保持引用不变，主流程可见

## 4. 技术亮点

### 4.1 创新点

1. **两段式 Hook**：明确区分推理前/后干预，时机清晰
2. **自注册机制**：装饰器自动注册，主流程无需感知具体 Hook
3. **异常隔离**：单个 Hook 异常不影响整体，提升稳定性
4. **原地修改约定**：通过引用共享实现数据传递，避免显式回写

### 4.2 难点攻克

| 难点 | 解决方案 |
|---|---|
| Hook 执行顺序不确定 | 按注册顺序遍历，保证确定性 |
| 原地修改约定难以理解 | 文档明确说明 + 代码注释强调 |
| Hook 间相互影响 | 每个 Hook 独立，不共享状态 |
| Hook 性能影响主流程 | Hook 执行时间计入埋点，可监控 |

### 4.3 设计权衡

| ���策 | 选择 | 理由 |
|---|---|---|
| Hook 是否支持异步 | 否，同步执行 | 简化实现，避免异步复杂度 |
| Hook 是否支持优先级 | 否，按注册顺序 | 避免优先级冲突，保持简单 |
| Hook 是否支持条件启用 | 否，在 Hook 内部判断 | 灵活性更高，避免框架复杂度 |
| Context 是否可整体替换 | 否，只能原地修改 | 保证引用共享，避免数据丢失 |

## 6. 面试要点

### 6.1 核心问题

**Q: 为什么选择两段式 Hook 而不是单段式？**

A: 推理前和推理后的干预目标不同：
- **推理前**：修改输入（chat_history、system_prompt），影响模型决策
- **推理后**：修改输出（tool_call_response），影响工具执行

两段式明确区分干预时机，避免混淆。单段式会导致 Hook 内部需要判断当前是推理前还是推理后，增加复杂度。

**Q: 为什么要求原地修改而不是整体替换？**

A: Context 与主流程共享同一对象引用：
- **原地修改**：保持引用不变，主流程可见修改
- **整体替换**：创建新对象，主流程仍持有旧引用，修改被静默丢弃

原地修改约定保证数据一致性，避免难以调试的"修改不生效"问题。

**Q: 如何保证 Hook 的执行顺序？**

A: 按注册顺序遍历执行。注册顺序由 Python 模块加载顺序决定，通常是文件名的字典序。如果需要特定顺序，可以在文件名中添加数字前缀（如 `01_panel_stale.py`）。

**Q: Hook 异常如何处理？**

A: 每个 Hook 独立 try-except，异常只记录日志，不抛出。这样设计的原因：
1. **稳定性**：单个 Hook 异常不影响其他 Hook 和主流程
2. **可观测性**：异常日志明确标识 Hook 名称，便于定位
3. **降级策略**：Hook 是"锦上添花"，异常时降级为不干预

### 6.2 延伸问题

**Q: 如果要新增一个 Hook，怎么做？**

A: 只需 3 步：
1. 在 `agent/pro/hooks/` 下创建新文件（如 `my_hook.py`）
2. 使用 `@register_pre_hook` 或 `@register_post_hook` 装饰函数
3. 在 `agent/pro/hooks/__init__.py` 中导入该模块

无需修改主流程代码，无需重启服务（如果支持热加载）。

**Q: Hook 的性能影响如何监控？**

A: 通过埋点监控：
1. 在 `run_pre_hooks` 和 `run_post_hooks` 中记录每个 Hook 的执行时间
2. 写入 `turn.stat`，随请求日志落盘
3. 可聚合分析 Hook 的平均执行时间、P99 延迟

**Q: 如果 Hook 之间需要共享数据怎么办？**

A: 两种方案：
1. **通过 Context 传递**：在 Context 中添加临时字段（不推荐，污染 Context）
2. **使用全局状态**：如 `contextvars`（推荐，隔离性好）

**Q: Hook 机制与 Patch 系统的区别是什么？**

A: 
- **Hook**：修改推理前/后的产物（chat_history、tool_call），owner 是主流程
- **Patch**：修改工具集（注入/剔除工具），owner 是 `_resolve_tools`

两者职责不同，避免并行数据源。如果 Hook 也改工具集，会导致 Patch 和 Hook 两个数据源并行，难以维护。
