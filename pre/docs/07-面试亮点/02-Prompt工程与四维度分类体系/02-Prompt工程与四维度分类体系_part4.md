## 8. 面试问答准备

### Q1: 为什么选择四维度而不是一维度？

**A**: 
1. **可解释性**：一维度直接输出easy/complex，无法知道原因；四维度可以清楚知道是哪个维度导致complex
2. **可维护性**：业务规则变化时，一维度需要重新训练模型；四维度只需修改Prompt中的规则
3. **准确率**：一维度准确率只有85%；四维度通过拆解问题，准确率提升到96%
4. **调优难度**：一维度准确率低时，难以定位问题；四维度可以分别分析每个维度的准确率

### Q2: 如何保证四个维度的正交性？

**A**:
1. **维度选择**：选择与业务决策强相关的维度，避免冗余
2. **标签定义**：每个维度的标签定义清晰，避免交叉
3. **强绑定规则**：对于确实有依赖关系的维度（如pend→vague），通过强绑定规则处理
4. **验证方法**：通过相关性分析，验证维度间的独立性

### Q3: 50次迭代的具体方法是什么？

**A**:
1. **收集错误case**：从测试集和生产环境收集错误case
2. **分析错误原因**：分类错误原因（边界case、定义不清、规则缺失等）
3. **定位问题维度**：确定是哪个维度的哪个标签出错
4. **修改Prompt**：针对性修改分类标准、规则或示例
5. **验证效果**：在测试集上验证准确率提升
6. **回归测试**：确保整体准确率不下降
7. **提交更新**：记录变更原因和效果

### Q4: 如何处理边界case？

**A**:
1. **扩展规则**：补充说明边界case应该如何判断
2. **排除规则**：明确不属于该标签的情况
3. **优先级规则**：当多个标签都符合时，按优先级选择
4. **典型示例**：通过示例帮助模型理解边界case
5. **强绑定规则**：对于确实有依赖关系的维度，通过强绑定规则处理

### Q5: 如果准确率还是不够，如何进一步优化？

**A**:
1. **增加示例**：添加更多典型示例，覆盖更多边界case
2. **优化工具定义**：改进工具定义的描述，减少歧义
3. **Few-shot学习**：在Prompt中添加更多示例，帮助模型学习
4. **模型微调**：使用标注数据微调模型，提升准确率
5. **集成学习**：使用多个模型投票，提升准确率
6. **人工审核**：对于低置信度的预测，交给人工审核

### Q6: 这个方案有什么局限性？

**A**:
1. **依赖LLM能力**：准确率受限于LLM的理解和推理能力
2. **Prompt长度限制**：分类标准和示例占用大量token，可能超出上下文窗口
3. **延迟较高**：需要生成4个标签，延迟比一维度高
4. **规则维护成本**：业务规则变化时，需要人工修改Prompt
5. **边界case难以穷举**：总有一些边界case无法覆盖

### Q7: 如何评估Prompt的质量？

**A**:
1. **准确率**：在测试集上的分类准确率
2. **格式正确率**：输出格式是否符合要求
3. **一致性**：相同query多次预测结果是否一致
4. **可解释性**：分类结果是否符合人类直觉
5. **鲁棒性**：对query的微小变化是否敏感
6. **效率**：生成延迟和token消耗
