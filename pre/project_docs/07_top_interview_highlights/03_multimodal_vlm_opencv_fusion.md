## 背景与问题定义

### 业务场景

简历 PDF 里通常有头像（右上角、左上角），需要：
1. 定位头像区域
2. 裁剪 crop（含合理边距）
3. 输出为图片，供渲染时嵌入模板

### VLM 单路径的三个问题

| 问题 | 表现 | 频次 |
|:---|:---|:---:|
| **VLM 偶发失败** | 网络抖动 / 内容审核 / 内部错误 | ~3-5% |
| **VLM 返回"疑似正确但错误"** | crop 了一片墙壁 / 剪了一半脸 | ~2% |
| **异常产物被缓存** | 下次同一份 PDF 直接命中"垃圾产物" | 放大失败 |

**放大效应**：VLM 失败率 3% + 缓存污染 → 用户看到的失败率反而**上升**（因为缓存击穿到坏结果）。

## 方案演进与关键决策

### 方案 A（初版，淘汰）：纯 VLM

```python
avatar = vlm_extract_avatar(pdf_image)
cache.set(pdf_hash, avatar)
return avatar
```

**问题**：见上文三个痛点。

### 方案 B（当前）：VLM + OpenCV 双路 + 质量校验

```
              ┌──────────────────┐
              │ VLM 主路径         │
              │ (高准确率、慢)    │
              └───────┬──────────┘
                      │
              ┌───────┴──────────┐
              │ VLM 输出质量校验   │
              │ 检查 bbox / 有效性│
              └───┬───────────┬──┘
                  │           │
              成功 │           │ 失败/可疑
                  ↓           ↓
              [使用 VLM]   ┌──────────────────┐
                  │        │ OpenCV 兜底路径    │
                  │        │ (Haar/DNN, 快、离线)│
                  │        └───────┬──────────┘
                  │                │
                  ↓                ↓
              ┌────────────────────────────┐
              │  产物质量最终校验             │
              │  bbox 面积 / 长宽比 / 是否包含人脸│
              └───────┬───────────┬────────┘
                      │           │
                  合格 │           │ 不合格
                      ↓           ↓
                  [入缓存]   [不入缓存 + 返回无头像]
```

### 关键决策 1：为什么选 OpenCV 作兜底而非另一个 VLM

- **VLM 兜底**：仍受网络 / 审核 / 成本影响，且失败模式**同源**（同一个 VLM 家族问题都在）
- **OpenCV**：离线、零延迟、失败模式与 VLM 独立
- **组合价值**：两路失败模式独立 → 总体失败率 ≈ 单路失败率²

**成本对比**：
| 路径 | 单次调用 | 延迟 | 准确率 | 独立故障域 |
|:---|:---:|:---:|:---:|:---:|
| VLM | ¥ | ~2s | ~95% | 云侧 |
| OpenCV | 0 | ~50ms | ~80% | 本地 |

### 关键决策 2：为什么"异常产物不入缓存"

**反直觉但关键**：
- 常规缓存策略：所有结果都入缓存
- 本场景：**入缓存前必须质量校验**，因为——
  - VLM 失败会走"纯文字兜底"路径，兜底质量本身差
  - 一旦缓存，同一份 PDF 永远拿到差结果
  - 相当于把 3% 的偶发失败**放大为**同一 hash 下的 100% 失败

**修复原则**：**Cache Quality Precondition**（缓存的前置条件是产物质量合格）

### 关键决策 3：网关矩阵适配（团队协作案例）

**背景**：07-17 司棋把 LLM 网关从"玄机 → BlueClaw"迁移，我的 VLM 调用在 07-27 上线时触发 `internal_error`。

**根因**：VLM 调用未适配 `BLUECLAW_NETWORK` 矩阵（dev/pre/prd 三套环境）。

**修复**：同日补齐 VLM 侧网关矩阵，与 blueclaw_chat.py 对齐。

**面试点**：这是**跨模块基础设施变更 + 上层适配**的协作案例，可讲**如何快速响应基础设施变化**。

## 算法/工程实现细节

### VLM 输出质量校验

```python
def validate_vlm_output(bbox, image_size):
    x1, y1, x2, y2 = bbox
    w, h = x2 - x1, y2 - y1
    img_w, img_h = image_size

    # 规则 1：bbox 应在图像内
    if not (0 <= x1 < x2 <= img_w and 0 <= y1 < y2 <= img_h):
        return False, "out_of_bounds"

    # 规则 2：面积合理（不能太小/太大）
    area_ratio = (w * h) / (img_w * img_h)
    if not (0.005 <= area_ratio <= 0.2):
        return False, "area_unreasonable"

    # 规则 3：长宽比接近人脸（0.7 ~ 1.4）
    if not (0.7 <= w/h <= 1.4):
        return False, "aspect_ratio_off"

    return True, "ok"
```

### OpenCV 兜底

```python
face_cascade = cv2.CascadeClassifier("haarcascade_frontalface_default.xml")
# 或使用更强的 DNN face detector（模型：res10_300x300_ssd_iter_140000.caffemodel）

def opencv_detect_face(image):
    gray = cv2.cvtColor(image, cv2.COLOR_BGR2GRAY)
    faces = face_cascade.detectMultiScale(gray, 1.1, 4, minSize=(60, 60))
    if len(faces) == 0:
        return None
    # 优先取最大人脸（简历头像通常最大）
    x, y, w, h = max(faces, key=lambda f: f[2] * f[3])
    # 扩展边距（避免只剪脸不剪头发）
    margin = int(0.3 * h)
    return (max(x-margin, 0), max(y-margin, 0),
            min(x+w+margin, image.shape[1]), min(y+h+margin, image.shape[0]))
```

### 缓存前校验

```python
def cache_avatar(pdf_hash, avatar_bytes):
    if not is_valid_avatar(avatar_bytes):
        # 不入缓存！允许下次重新计算
        return
    cache.set(pdf_hash, avatar_bytes, ttl=7*86400)
```

## 方法论抽象与迁移

### 多模态融合三原则

1. **失败模式独立**：兜底路径必须与主路径**不同故障域**（云 vs 本地、深度 vs 传统、模型 A vs 模型 B）
2. **质量校验必须显式**：不能默认"模型输出=合格"，要有**独立校验层**
3. **缓存前置校验**：缓存机制不能盲目相信生产者

### 可迁移场景

| 场景 | 迁移点 |
|:---|:---|
| **OCR 提取** | LLM OCR + Tesseract 双路兜底 |
| **语音识别** | 云 STT + 本地 STT 双路 |
| **翻译服务** | LLM 翻译 + 传统统计翻译兜底 |
| **通用 LLM 结果** | 主模型 + 弱兜底模型 |

### 反例警示

- **反例 1**：用另一个 VLM 兜底 —— 失败模式同源，白搭
- **反例 2**：不做缓存校验 —— 一次故障放大为长期故障
- **反例 3**：OpenCV 参数不调 —— 默认 Haar 对亚洲人脸检测率低
