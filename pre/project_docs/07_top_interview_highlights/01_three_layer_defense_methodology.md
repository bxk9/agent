# 01 · 三层防御方法论：LLM 结构化输出的 Schema × 正则 × 归一化

> **作者**：11099826 · **场景**：简历 AI 提取字段幻觉治理 · **迁移方**：陈乾（复盘 skill 三层拦截）

---

## 一句话摘要

面对 LLM 输出"结构不对 / 值幻觉 / 格式漂移"三类幻觉，我抽象出**"Schema 强约束 → 正则语义校验 → 归一化落表"三层递进防御**：每一层只解决一类问题，前一层过滤越多、后一层越轻，最终把可信数据交付业务。这套方法论被团队复用到 5+ 场景。

## 背景与问题定义

### 业务场景

简历生成场景：用户上传 PDF/Word，需要 LLM 提取**结构化字段**（姓名/教育/工作经历/项目/技能/奖项/语言/爱好等 15+ 字段），下游要按模板渲染成简历文档。

### 三类幻觉痛点

| 类型 | 表现 | 治理前故障率 |
|:---|:---|:---:|
| **结构幻觉** | `education` 应为 list，模型输出成 dict / string | ~8% |
| **值幻觉** | 编造工作经历、幻觉出用户未提到的项目 | ~15% |
| **格式幻觉** | 日期 `2020.3` / `2020年3月` / `20-3` / `2020/03` 混用 | ~30% |

### 为什么难

- **结构幻觉**：靠 prompt 硬约束（"必须输出 list"）→ 少量样本仍失败
- **值幻觉**：LLM 天然会补全，尤其"看似合理"的字段
- **格式幻觉**：训练数据本身就格式多样，模型不会强制统一

**核心洞察**：这三类问题的**根因不同**、**发现时机不同**、**修复成本不同**——不能用同一层解决。

## 方案演进与关键决策

### 方案 A（淘汰）：单靠 Prompt 约束

```
"请以 JSON 格式输出，education 必须是 list，日期格式为 YYYY-MM ..."
```

**结果**：
- 简单样本 OK
- 复杂样本（长 PDF、多语言）失败率仍 5%+
- prompt 越写越长，最终超过 2000 字仍不稳定

**淘汰原因**：prompt 是"祈祷式约束"，无强制力。

### 方案 B（淘汰）：全靠后处理 clean

```python
def clean_llm_output(data):
    # 100+ 个 if/else 分支
    if isinstance(data.get("education"), str):
        data["education"] = [data["education"]]
    if "-" in data.get("date", ""):
        data["date"] = normalize_date(data["date"])
    ...
```

**结果**：clean 函数变成"上帝对象"，无法维护。

**淘汰原因**：所有问题混在一层，责任不清、可扩展性差。

### 方案 C（采用）：三层递进防御

```
   LLM 原始输出
        ↓
┌───────────────────────┐
│ 第一层：Schema 强约束  │  ← 结构幻觉
│  Function Calling /   │
│  JSON Schema         │
└───────────────────────┘
        ↓
┌───────────────────────┐
│ 第二层：正则语义校验    │  ← 值幻觉（部分）+ 格式幻觉
│  日期/邮箱/URL/电话   │
│  正则组 + 拒绝式补正   │
└───────────────────────┘
        ↓
┌───────────────────────┐
│ 第三层：归一化落表     │  ← 格式幻觉终点
│  统一到 canonical form │
└───────────────────────┘
        ↓
   业务层可信数据
```

### 关键决策 1：为什么 Schema 放最外层

- Schema 是**唯一有强制力**的层（LLM 网关直接拒绝不合规输出）
- 拦截率最高（结构幻觉基本清零）
- 后续两层的输入被大幅简化

### 关键决策 2：为什么正则不做归一化

**分工清晰**：
- 正则层：**判断合法性**（合法/不合法 → 拒绝 or 拒绝式补正）
- 归一化层：**统一形式**（`2020.3` / `2020/03` → `2020-03`）

如果混在一起，正则会变得像方案 B 的 clean 一样臃肿。

### 关键决策 3：拒绝式补正

第二层不做"猜测补全"，而是——
- 合法 → 通过
- 不合法但可提示 → 回给 LLM 重试（限 1 次）
- 不合法且不可提示 → 置空 + 标记

**不做猜测**是有意的：宁可字段为空，也不给用户看到"编造的手机号"。

## 算法/工程实现细节

### 第一层：Schema（Function Calling）

```python
resume_schema = {
    "type": "object",
    "properties": {
        "basic": {"type": "object", "properties": {...}},
        "education": {
            "type": "array",
            "items": {
                "type": "object",
                "required": ["school", "start_date", "end_date"],
                "properties": {
                    "school": {"type": "string"},
                    "start_date": {"type": "string", "pattern": "^\\d{4}-\\d{2}$"},
                    ...
                }
            }
        },
        "extra_sections": {"type": "object", ...}
    }
}
```

**要点**：
- required 字段严格声明
- pattern 做最基础的格式约束
- extra_sections 放"可选章节"（奖项/语言/爱好），避免主字段污染

### 第二层：正则语义校验

```python
DATE_PATTERN = re.compile(r"^\d{4}[-./年]\d{1,2}([-./月]\d{1,2}[日]?)?$|^\d{4}$")
EMAIL_PATTERN = re.compile(r"^[\w.+-]+@[\w-]+\.[\w.-]+$")
PHONE_PATTERN = re.compile(r"^1[3-9]\d{9}$")

def validate_field(name, value):
    if name in DATE_FIELDS and not DATE_PATTERN.match(value):
        return None, "date_invalid"  # 触发重试
    ...
```

**关键点**：
- 不是简单的"提取合法值"，而是"判定 + 分类拒绝原因"
- 拒绝原因返回给 LLM，配合"重试引导"

### 第三层：归一化

```python
def normalize_date(s):
    """把 2020.3 / 2020年3月 / 20/03 都归一到 2020-03"""
    for p in [r"^(\d{4})[.\-/年](\d{1,2})", r"^(\d{2})[.\-/](\d{1,2})"]:
        m = re.match(p, s)
        if m:
            y, mo = m.groups()
            if len(y) == 2: y = "20" + y
            return f"{y}-{int(mo):02d}"
    return s
```

**要点**：
- 归一化目标是**canonical form**（唯一形式）
- 下游渲染器只需处理 canonical form，简化 15+ 模板的模板代码

## 量化验证与效果

| 指标 | 治理前 | 三层防御后 | 备注 |
|:---|---:|---:|:---|
| 结构幻觉率 | 8% | **<0.1%** | Schema 兜底 |
| 值幻觉率（可检测部分） | 15% | **~2%** | 正则拒绝 + 重试 |
| 格式幻觉率 | 30% | **0%** | 归一化终止 |
| 渲染失败率（下游） | 12% | **<1%** | 综合改善 |

## 方法论抽象与迁移

### 可复用原则

**"分层拦截 + 层内单职责"**：

| 原则 | 说明 |
|:---|:---|
| 每层只解决一类问题 | Schema 管结构、正则管语义、归一化管形式 |
| 前置层拦截率越高越好 | 减轻后置层负担 |
| 不做猜测补全 | 幻觉修复的最坏结果是**新幻觉** |
| 保留 "reject with reason" | 给上游/LLM 重试机会 |

### 已成功迁移的场景

| 场景 | 迁移方 | 三层映射 |
|:---|:---|:---|
| **复盘 skill 交付拦截** | 陈乾 | Skill 软约束 → 交付前自检 → 工具入库拒绝 |
| **VLM 图像版式提取** | 11197109 | VLM Prompt 约束 → 结构后处理 → 字段归一化 |

### 失败模式警示

- **反例 1**：某个字段"Schema + 正则 + 归一化"三层都能处理 → **只放最后一层就行**（避免过度设计）
- **反例 2**：把归一化做在正则层 → 无法区分"值错"和"格式错"
