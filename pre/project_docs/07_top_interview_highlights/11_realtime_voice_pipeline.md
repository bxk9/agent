## 背景与问题定义

### 面试场景对语音的要求

1. **首字节延迟 < 1s**：用户说完一句话到听见 AI 首字，超过 1s 就"面试感"崩塌
2. **打断自然**：用户想打断 AI 时能立刻停
3. **角色稳定**：AI 面试官不能随机变成"AI 助手"口吻
4. **多轮上下文**：一场面试 20+ 轮不出戏

### 天真实现的问题

**方案 A：非流式全链路**
```
STT 转完整文本 → LLM 生成完整回答 → TTS 合成完整音频 → 播放
```
延迟 = STT (1s) + LLM (3-5s) + TTS (2s) = **6-8s** → 不可接受

**方案 B：只 LLM 流式，其他串行**
```
STT → LLM 流式 → 等 LLM 结束 → TTS
```
延迟仍 = STT + LLM 首字 + 等 LLM 结束 + TTS = **仍然 4-5s**

---

## 方案：全链路流式 + 打断闭环

### 核心架构

```
用户音频流
    ↓
【VAD 检测】────────触发打断→──┐
    ↓                          │
【STT 流式转文本】               │
    ↓（partial → final）        │
【LLM 流式生成】←───────────────┤
    ↓（token 流）               │
【TTS 流式合成】←───────────────┤
    ↓（音频 chunk）              │
【前端播放队列】←───flush 指令───┘
```

### 关键决策 1：三段流水线全流式

- STT：不等用户说完，边说边转（partial results）
- LLM：拿到 final 后立刻流式生成
- TTS：拿到 LLM 首个短句就开始合成播放

**收益**：首字节延迟压到 **~600-900ms**

### 关键决策 2：首句短、后句长

- Prompt 设计让 LLM 先出一个短句（如"嗯，你的意思是..."）
- 短句 TTS 快、缓冲后续
- 用户感知延迟极短

**这是 yitong 主导的 prompt 策略**——具体在陈妮的对话 prompt 中落地。

### 关键决策 3：打断闭环

```
用户开始说话（VAD 触发）
    ↓
立刻发 flush 指令给 TTS 队列
    ↓
清空前端播放队列
    ↓
记录"AI 说到哪被打断"到上下文
    ↓
新 STT 流开始
```

**关键**：打断时**上下文要记录 AI 实际"说到哪"**，而不是记录 LLM 完整回答。否则用户以为打断了、AI 以为自己讲完了。

---

## 算法/工程实现细节

### VAD 阈值调优

- 太敏感：环境噪音触发打断
- 太钝：用户抢话不生效
- 实测：**300ms 连续有声 + 能量阈值** 组合最佳

### STT partial → final 切换

- partial 阶段：给 LLM 但不真的调用
- 达到"稳定 partial"（连续 N 次不变）：预调用 LLM
- final：正式确认

**预调用**是 yitong 的耗时优化方法论（07 号文档）的实践迁移。

### TTS 流式的坑

- 短句独立合成会有"每句起音突兀"
- 解决：**跨句 crossfade 100ms**
- 声学连贯性提升明显

### 角色稳定：prompt 稳态

- 面试官人设 = system prompt 硬性写死
- 每 5 轮插入一次"你是面试官"reminder（陈妮的对话 prompt 策略）
- 用户如果 jailbreak → LLM 硬拒绝

## 方法论抽象与迁移

### 实时语音的三大铁律

1. **全链路流式**：任何一段非流式都会毁掉体验
2. **首句短**：用户感知延迟 = 首字节延迟，不是总延迟
3. **打断必须做**：不能打断的语音不是"实时"

### 与延迟优化方法论（07 号）的关系

- 07 号是通用方法论（观测 → 剖分 → 优化）
- 本篇是具体场景的落地
- 两者一起讲最完整

### 可迁移场景

| 场景 | 迁移点 |
|:---|:---|
| **实时语音助手** | 完全适用 |
| **直播实时字幕/翻译** | 三段流水线相似 |
| **游戏 NPC 语音** | 首句短、打断闭环 |
| **客服实时通话** | 角色稳定、打断处理 |

### 反例警示

- **反例 1**：不做流式 → 6-8s 延迟直接崩
- **反例 2**：不记录"AI 说到哪被打断" → 上下文永久错位
- **反例 3**：不做 prompt 稳态 → 20 轮后 AI 变成"通用助手"
