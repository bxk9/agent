## 五大原创约束

### 1. 整体盘点前置

**背景**：模型倾向逐题输出，忽略全局评估
**约束**：Skill 强制第一节输出整体盘点（策略、节奏、致命问题）

### 2. 逐题全覆盖 + 交付前自检

**背景**：模型会跳题、并题、漏题
**约束**：
- 硬约束"必须覆盖所有题目"
- 交付前对齐题数自检
- 08-07 配套 `save_review_report` 交付层拦截漏题

### 3. 数字铁律

**背景**：模型倾向编造数字（如"提升30%"）
**三层约束**：
- 无数字必占位（`[数据待补]`）
- 有数字必对齐原话
- 背景/情景数字禁编造（07-22 补充反例）

### 4. 硬闸机制

**背景**：模型在语音转写后有时跳过复盘 skill 直接输出
**约束**：业务动作前置硬闸——检测到"复盘"场景必须走 skill
**收窄**：仅约束复盘场景，不干扰简历/面试其它流程

### 5. 同音变体处理

**背景**：ASR 常把"React" 误识为"日刻"、"K8s" 识为"卡8s"
**约束**：
- 专名同音变体按误识还原
- 原话保原样、分析用标准术语
- 不提"转写误差/统一术语"（避免用户误解为系统 bug）

---

## 方法论提炼

陈乾的复盘 skill 展现了**"业务约束 → 反例驱动 → 收窄边界"**的三段式提示词工程：

1. **业务约束**：从业务视角先提"该做什么、不该做什么"
2. **反例驱动**：踩过的坑写成反例注入 skill（例："背景数字编造反例"）
3. **收窄边界**：一旦发现约束误伤其它场景，立即加"场景守卫"（例：硬闸收窄）
