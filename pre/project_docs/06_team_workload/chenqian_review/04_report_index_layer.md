# 04 · 跨会话复盘报告索引层

## 一句话概括

陈乾在 07-09 建立 **save_review_report / query_review_reports 双工具 + 索引层**——让复盘报告脱离单个会话，成为**可跨会话管理、可搜索的用户资产**。

---

## 背景

### 之前的问题

- 复盘报告只存在于生成它的那个会话里
- 用户第二天想再看 → 找不到
- 想对比多场面试 → 无处对比

### 目标

- 报告持久化、可检索
- 与错题本、简历一样成为**"用户资产"**
- 支持后续 mock 面试或简历生成引用

## 双工具设计

### save_review_report

```
输入：
  - HTML 报告内容 / VFS 链接
  - 元数据（岗位、时间、题数、评分）
输出：
  - report_id
  - 索引条目
副作用：
  - 上传 HTML 到 VFS
  - 写入索引层
```

### query_review_reports

```
输入：
  - user_id
  - 过滤（岗位、日期范围、关键词）
输出：
  - 报告列表（含摘要、链接、评分）
```

### 索引层

- 以 user_id 为主 partition
- 支持岗位、日期、关键词过滤
- 与错题本、简历共用同一"用户资产"命名空间

## 交付前拦截（08-07）

### 问题

模型偶尔漏题（说 5 题却只分析了 3 题），复盘 skill 硬约束仍会被绕过。

### 方案

`save_review_report` 工具在**入库前**做题数自检：
- 对比 skill 声明题数 vs 实际逐题分析块数量
- 不一致 → 拒绝入库 + 记录原因
- 记录漏题原因用于后续 skill 迭代

### 与 skill 层配合

- Skill 层：软约束（提示模型全覆盖）
- Report 工具层：硬拦截（漏题不入库）
- 双层保险
