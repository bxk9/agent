## 演进路径

### 第一版：硬替换（08-03 上午）

```python
url.replace("http://internal.vfs", "https://public.vfs")
```

**问题**：写死域名，环境切换要改代码

### 第二版：环境变量（08-03 下午）

```python
if os.getenv("REWRITE_PUBLIC_URL"):
    url = do_replace(url)
```

**问题**：还是"替换"思路，模型看到的 URL 与真实 URL 不一致

### 第三版：内网 vfs 直用（08-04）

**新思路**：
- 音频文件直接用 vfs 内网链接（不做替换）
- 后端服务在内网可访问
- 模型输出的 URL 就是最终 URL

**收益**：
- 简化流程
- URL 与日志一致
- 无中间转换成本

### 第四版：public 开关（08-04）

**边缘场景**：某些下游确实需要 public 短链
**方案**：`GET_AUDIO_PUBLIC_URL` 环境变量开关
- 关闭（默认）：用内网 vfs 链接
- 开启：**额外**签发 public 短链（不是替换，是叠加）

---

## 设计原则

陈乾这四步展现了**"从改造到废弃"**的迭代智慧：

1. **第一版**：解决问题（硬编码）
2. **第二版**：可配置（环境变量）
3. **第三版**：**改变问题**（直接用内网，不再替换）
4. **第四版**：把废弃的能力作为开关保留，向下兼容

比"逐步优化"更高级的是"重新审视问题本身"。
