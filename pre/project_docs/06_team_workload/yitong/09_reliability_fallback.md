# 专题 09｜稳健性与兜底机制

> 版本：v1.0

---

## 一、总述：LLM 智能体的"不可靠性乘法"

Interview Agent 的稳定性挑战比传统后端服务高一个数量级：

```
最终成功率 = P(网络) × P(第三方模型) × P(LLM 遵从) × P(工具调用正确) × P(数据结构) × P(渲染)
```

每一环即使 95% 成功，六环相乘也只剩 73%。因此本项目采用**多层兜底 + 主动降级**的策略。以下罗列我参与建设的稳健性机制。

---

## 二、兜底机制清单

### 2.1 模型层：v4 pro 兜底

```
提交：增加兜底v4 pro模型
```

主模型失败（超时/限流/协议错误）时自动切换到 v4 pro 模型，保证请求成功率。

### 2.2 Prompt 层：FALLBACK 简版人设

```
提交：voice: 单一 prompt 源 + 流式 LLM + FALLBACK 兜底 + 面经正文透传
```

主 Prompt 生成失败时（如简历摘要 LLM 调用失败），使用固化的简版面试官人设，保证不断线。

### 2.3 数据层：VLM 异常降级 + 缓存污染防护

见 `docs/fix/20260806_VLM异常降级与缓存污染防护_根因分析与修复方案.md`。VLM 异常时不写缓存，并降级到 fitz 纯文本解析。

### 2.4 解析层：JSON 部分解析

```python
# raw_decode 只取第一个有效 JSON，容忍尾部自然语言
decoder = json.JSONDecoder()
data, _ = decoder.raw_decode(raw.lstrip())
```

### 2.5 渲染层：三重防线（Schema → 自动降级 → 兜底闸）

见 [`04_llm_latency_optimization.md`](./04_llm_latency_optimization.md) §5.2：

| 层 | 时机 | 作用 |
|---|-----|------|
| 事前约束（Schema） | LLM 生成前 | 限制输入结构 |
| 事后降级 | 工具执行入口 | 自动提取 scope 字段 |
| 兜底闸 + DOM 替换 | 渲染阶段 | diff 补标 + 局部替换 |

### 2.6 数据结构层：空 choices 防御

```python
# 之前
content = resp["choices"][0]["message"]

# 之后
if not resp.get("choices"):
    logger.warning("empty choices, skip usage")
    return
content = resp["choices"][0].get("message", {})
```

### 2.7 错题本重试机制

```
提交：语音错题本识别增加重试机制
```

LLM Judge 失败时最多重试 3 次，指数退避（1s / 2s / 4s）。

### 2.8 上下文裁剪防膨胀

```
提交：语音上下文裁剪
提交：blueclaw_chat增加裁剪和日志
```

- `_MAX_MEMORY_CHARS = 50000`
- 超限时按最近优先截断
- 前后长度打日志

### 2.9 recursion 限制

`_RECURSION_LIMIT = 25`，防止工具循环调用把整个链路拖挂。

### 2.10 断连宽容

```
提交：增加断开时长
```

允许一定的 idle 时间不断开，避免语音链路在用户思考期间掉线。

### 2.11 deeplink onceClick

```
提交：deeplink增加&onceClick=true限制单次点击
```

防止用户重复点击导致的重复触发。

### 2.12 批量删恢规避 limit

```
提交：增加批量删除和恢复错题本功能，解决大量单题删除引起的limit限制
```

底层 API 有频率限制，批量接口把 N 次调用合并为 1 次。

## 三、稳健性设计矩阵

| 失败类型 | 我方兜底 | 是否有日志 | 是否可恢复 |
|---------|---------|-----------|----------|
| 主模型超时/限流 | v4 pro 切换 | ✅ | ✅ |
| Prompt 生成失败 | FALLBACK 简版 | ✅ | ✅ |
| VLM 异常 | fitz 降级 | ✅ | ✅ |
| JSON 解析失败 | raw_decode | ✅ | ✅ |
| LLM 输出全量（应精简） | 三重防线 | ✅ | ✅ |
| 空 choices | 提前 return | ✅ | ✅ |
| Judge 网络失败 | 3 次重试 | ✅ | ✅ |
| 上下文膨胀 | 裁剪 | ✅ | ✅ |
| 工具循环 | recursion 25 | ✅ | ❌（硬中断） |
| 网络抖动 | idle 宽容 | ✅ | ✅ |
| 用户误点 | onceClick | — | ✅ |
| API limit | 批量接口 | — | ✅ |

**结论**：12 类典型失败已建立对应兜底路径，其中 11 类可自动恢复。

## 四、设计原则

### 4.1 分层原则
每一层都假设下一层可能失败，独立防御。

### 4.2 快速失败 vs 优雅降级
- **快速失败**：违反核心约束（如 recursion 上限）→ 立即中断
- **优雅降级**：单点异常 → 走备用路径 + 记录日志

### 4.3 兜底不能替代修复
每次兜底触发都必须记入日志并复盘，避免长期依赖兜底掩盖根因。

### 4.4 兜底代价可视化
每条兜底路径都有明确的性能/体验代价说明（如 fitz 降级 = 丢失版式）。
