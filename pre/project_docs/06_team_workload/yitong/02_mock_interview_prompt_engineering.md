## 一、为什么 Prompt 工程占了这么大工作量

Interview Agent 是一个**产品驱动**的智能体：
- 语音面试要拟人、要克制、要有节奏感
- 文字面试要能逐题点评、集中点评、复盘
- 两条通道要能互相衔接不断裂
- 每条策略都可能引发下游 Bug（比如"点评被切通道"）

因此我采用了 **"实测→根因→Prompt 编码→回归"** 的迭代循环，每一条产品反馈几乎都能追踪到一次提交。

### 2.2 07-30 的"12 条硬约束单次提交"

这是最能代表迭代密度的一次提交，一次性锁死语音面试的产品形态：

```
提交时间：2026-07-30 23:35
提交信息：
  1. 语音面试点评策略调整：从不提供反馈改为面试结束后通过复盘完成点评
  2. 路由规则加固：用户要求点评/逐题反馈不改变路由结果
  3. 面试结束评估：整体评估中去掉共N题计数
  4. 出题前缀：**题目** → **第N题**
  5. 出题依据话术统一：简化为基于联网搜索到的N条面经
  6. 配置变更统一：无论改什么配置，一句话告知
  7. 冲突检查升级为全局规则
  8. 反馈中立性：只描述事实缺口
  9. 配置不重复
  10. 不主动剧透题目
  11. 语音链接必须重新输出占位符
  12. 面试结束不直接给总结（先询问）
```

**背后的方法论**：每条策略都对应此前收集的一类用户反馈或线上问题；提交前用 3 个典型 case 做回归验证。

## 三、Prompt 设计原则（从实践中沉淀）

> 以下 8 条原则来自我在 165+ 次 Prompt 提交中反复验证得出。

### 原则 1：先写"禁止"再写"应当"
LLM 对"禁止 X"的遵从度显著高于"应当 Y"。语音面试中所有关键行为约束（禁止点评、禁止无限追问）都以否定句先行。

### 原则 2：一条策略 → 一条硬编码
避免"根据情况判断"，而是把判断规则写死。例如"用户要求点评"这种 case，不留裁量空间，直接指定路由。

### 原则 3：话术模板 + 变量占位符
```
每次结束题目：直接问下一题
每次开始题目：**第{N}题**：{题目内容}
面试结束：**面试评估**\n{...}
```

### 原则 4：反例日志优先
在 Prompt 中引用真实错误 case（如"过去出现过 150 分钟无限输出"），LLM 对反例的规避比对正例的模仿更稳定。

### 原则 5：单一 Prompt 源
所有拼装点收敛到单个 `.md` 文件，禁止运行时拼装多段。参见 07-23 `voice: 单一 prompt 源`。

### 原则 6：策略变更需要"话术同步"
每一次 Skill 内容改动，都必须评估是否需要同步 `_system_prompt.md`。多次提交题为"话术同步"就是这个原因。

### 原则 7：配置字段做减法
面试配置从初期"公司 + 岗位 + 难度 + 风格 + 语言 + 时长..." 精简为"公司/岗位/题目风格"三项，用户输入解析容错率↑。

### 原则 8：默认值即产品意图
"出题策略默认改为深度追问"（08-10）不是技术改动，而是**产品意图**：面试价值来自深度而非广度。
