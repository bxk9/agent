## 关键攻坚

### 1. BLUECLAW_NETWORK 矩阵适配（07-27）

**背景**：
- 07-17 司棋完成 LLM 网关从"玄机 → BlueClaw"迁移
- VLM 调用未同步适配 BLUECLAW_NETWORK 矩阵
- 上线后触发 `internal_error`

**修复**：
- VLM 调用链接入 dev / pre / prd 三套 BLUECLAW_NETWORK 环境
- 与 blueclaw_chat.py 的网关适配对齐
- 补日志便于后续排查

**协作证据**：这是团队协作的经典案例——底层司棋换基础设施，上层 11197109 补上视觉调用侧。

### 2. 默认模型切换（07-28）

**问题**：初期默认 VLM 模型识别质量不佳
**方案**：切换到更强的默认模型（并保留可配置）

### 3. 异常产物缓存污染（08-06）

**问题**：
- VLM 偶尔异常返回（例如网络抖动、内容审核触发）
- 系统落入"纯文字兜底"路径，但**兜底质量差**
- 更糟的是——**异常产物被缓存**！下次同一份 PDF 直接命中垃圾产物

**方案**：
- 异常产物**不进缓存**（识别失败标记）
- 纯文字兜底质量提升（补充结构化提示）
- 缓存命中前校验产物有效性
