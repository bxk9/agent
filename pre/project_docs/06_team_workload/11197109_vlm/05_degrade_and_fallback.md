# 05 · 降级兜底与产物修复

## 一句话概括

11197109 通过 **"降级兜底 + 缓存治理 + 静默丢失守卫"三招** 让 VLM 链路在 VLM 不可用、结果异常、缓存过期等极端场景下依然可交付。

---

## 三大守卫点

### 守卫 1：extra_sections 降级后静默丢失（07-31）

**问题**：
- 主 VLM 路径失败 → 走纯文字降级
- 降级路径**默默忽略**了 extra_sections（奖项、语言、爱好）
- 用户拿到的简历少了三块内容，且没有任何提示

**修复**：
- 降级路径显式保留 extra_sections
- 记录降级日志（后续可用于告警）

### 守卫 2：缓存命中过期链接透传（08-04）

**问题**：
- VLM 结果缓存以 URL 为 key
- 用户上传新简历，但走了缓存命中
- 缓存里存的是**旧 URL 的产物**，返回后 doc_agent 拿不到实际文件 → 空转

**修复**：
- 命中前校验产物链接是否有效
- 无效 → 缓存失效 + 重新计算
- 防止过期链接透传

### 守卫 3：异常产物缓存污染（08-06）

**问题**：
- VLM 异常返回（网络抖动 / 审核触发） → 落入纯文字兜底
- 兜底质量低 → 但**被缓存了**
- 下次同一份 PDF 直接命中垃圾产物

**修复**：
- 识别到异常产物 → 不进缓存
- 提升纯文字兜底质量（补充结构化提示）
- 缓存前的产物质量校验

---

## 兜底方法论

11197109 的兜底设计体现了**"降级不能是坑"**的原则：

| 反模式 | 正确做法 |
|:---|:---|
| 降级路径静默丢字段 | 降级路径必须覆盖完整字段 |
| 异常产物进缓存 | 异常必须标记，不污染缓存 |
| 缓存过期透传 | 命中前校验有效性 |
| 兜底质量凑合 | 兜底也必须可用 |
