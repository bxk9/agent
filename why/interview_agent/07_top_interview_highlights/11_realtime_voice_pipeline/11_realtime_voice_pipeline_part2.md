1. **全链路流式**：STT/LLM/TTS 三段流水线，首字节 <1s
2. **打断闭环**：flush + 播放位置记录，上下文不错位
3. **行为约束体系**：prompt 约束 → 强化 → 结构化槽位的三级演进

### 6.2 技术深度

1. **实时系统设计**：VAD、流式拼接、队列管理
2. **LLM 行为工程**：出题策略、点评时机、角色维持的系统性约束
3. **多人协作架构**：链路/策略/体验三层分离

### 6.3 业务价值

1. **面试临场感**：首字节延迟进入自然对话区间
2. **产品差异化**：深度追问 + 点评后置的完整面试体验
3. **稳定运行**：20+ 轮长对话不出戏、不中断

### 6.4 方法论抽象与迁移（原文档保留部分）

**实时语音的三大铁律**：

1. **全链路流式**：任何一段非流式都会毁掉体验
2. **首句短**：用户感知延迟 = 首字节延迟，不是总延迟
3. **打断必须做**：不能打断的语音不是"实时"

**与延迟优化方法论（07 号）的关系**：07 号是通用方法论（观测 → 剖分 → 优化），本篇是具体场景的落地，两者一起讲最完整。

**可迁移场景**：

| 场景 | 迁移点 |
|:---|:---|
| **实时语音助手** | 完全适用 |
| **直播��时字幕/翻译** | 三段流水线相似 |
| **游戏 NPC 语音** | 首句短、打断闭环 |
| **客服实时通话** | 角色稳定、打断处理 |

**反例警示**：

- **反例 1**：不做流式 → 6-8s 延迟直接崩
- **反例 2**：不记录"AI 说到哪被打断" → 上下文永久错位
- **反例 3**：不做 prompt 稳态 → 20 轮后 AI 变成"通用助手"
- **反例 4**：多份 prompt 维护 → 文字/语音行为不一致（07-28 三条"同步"提交是痛点证明）

## 7. 面试问答准备

### Q1: 首字节延迟怎么压到 1s 以内的？

**A**：
1. 全链路流式：STT 边说边转、LLM 流式生成、TTS 短句即播（`bd40e51`）
2. 首句短策略：prompt 让 LLM 先出短句，TTS 快速出声
3. 稳定 partial 预调用：STT 转写稳定后预热 LLM
4. 面经正文透传：减少一次 LLM 加工环节

### Q2: 打断时上下文怎么处理？

**A**：
1. VAD 触发 → 立刻 flush TTS 队列 + 清空播放
2. 关键：记录"AI 实际说到哪"（播放位置），不是 LLM 完整回答
3. 否则用户以为打断了、AI 以为自己讲完了——上下文永久错位
4. 新 STT 流开始，后续对话基于正确的上下文

### Q3: 为什么强制"每次只出一题"？

**A**：
1. 语音无法回看：批量出题用户只记住最后一题
2. 追问依赖上一题回答：批量出题 = 放弃追问（与深度追问策略冲突）
3. 题号混乱：多题并发导致与主题号冲突（`422609b`）
4. 约束演进：prompt 约束 → 强化 → 出题数量槽位（结构化参数）

### Q4: 为什么点评后置到复盘？

**A**：
1. 决策原文（`ff5f834`）："点评能力不缺失，只是时机不同"
2. 语音听点评体验差：300 字念 1 分钟，用户只能干听
3. 打断面试节奏：真实面试不会边面边评
4. 选择权给用户：结束后先询问是否需要整体点评

### Q5: 三人协作怎么不打架？

**A**：
1. 三层分离：张梦宇链路层、陈妮对话策略层、yitong 集成体验层
2. 策略迭代不动链路，体验调优不改策略结构
3. 单一 prompt 源（`bd40e51`）消灭"忘记同步"
4. 这是 60 天 60+ 次语音提交的组织基础
