> **选材原则（面试算法工程师视角）**：

> 5. **有真实业务场景背书**（不是玩具项目）

## 文档结构说明（v2.1 统一标准）

参照 `01-SGLang早停优化技术.md` / `01-SGLang早停优化技术-原因说明.md` 示例，全部 24 篇文档已按统一标准改写：

**亮点文档结构**：
1. **核心概览**（保留原文档精华）：一句话摘要 + 面试价值卡片 + 方案演进与关键决策（含淘汰方案）
2. 项目背景与问题定义（含量化瓶颈分析）
3. 技术方案设计（含规则表）
4. 核心实现细节（伪代码 + 逐步示例 + 边界 case）
5. 效果评估与优化（git 统计 + 收益）
6. 技术亮点总结（创新性/技术深度/业务价值 + **方法论抽象与迁移**）
7. 面试问答准备（Q1-Q5）
8. 代码文件索引
9. 总结（一句话总结）

**原因说明文档结构**：
1. **第一部分：简略分析**（原文档完整保留，除证据等级表）——便于快速理解
2. **第二部分：详细原因说明**——逐决策展开：来源（git/文档）+ 原文引用 + 详细解释 + 场景示例/技术对比
3. 总结（核心/技术/业务价值分类）
4. 参考资料（git 提交记录原文 + 相关文档）

## 每篇文档的深度结构

为面试展示优化，每篇文档采用**七段式深度结构**：

1. **一句话摘要**（30 秒电梯演讲）
2. **面试价值卡片**（能讲什么、能答哪些经典面试题）
3. **背景与问题定义**（业务上下文 + 为什么难 + 量化痛点）
4. **方案演进与关键决策**（不只是"怎么做"，还有"为什么这么做"、"淘汰了什么方案"）
5. **算法/工程实现细节**（伪代码、关键 diff、边界处理）
6. **量化验证与效果**（前后对比、A/B、指标）
7. **方法论抽象与迁移**（能否推广到其他场景、失败模式警示）
