- 第 11 条是附带治理：历史语音链接会过期，必须每次重新输出占位符

## 2.2 技术实现原因

### 2.2.1 为什么"每次只出一题"要反复强化（真实原因）

**来源**：git 提交记录 - `a490baa` → `25c2b95` → `6750181`

**提交信息原文**：
```
a490baa | 2026-07-31 | yitong | 每次只出一题，点评话术约束
25c2b95 | 2026-08-05 | yitong | 强化语音内部不能点评，文字逐题出
6750181 | 2026-08-05 | 陈妮   | 添加出题数量槽位，约束开场白及延伸不计入数量
```

**详细解释**：
- 07-31 落地，08-05 还要"强化"——LLM 有强烈的批量出题倾向，prompt 约束会被突破
- 约束手段三级演进：prompt 约束 → 持续强化 → 结构化槽位（出题数量参数）
- "开场白及延伸不计入数量"说明"什么算一道题"曾有歧义——槽位把定义也固化了
- 本质：LLM 行为约束要从"软约束"走向"结构化参数"

**约束演进**：
```
第 1 级（07-31）：prompt 写"每次只出一题"
  → LLM 偶尔仍出多题
第 2 级（08-05）：强化措辞 + 多场景覆盖（语音/文字）
  → 违规率下降但不归零
第 3 级（08-05）：出题数量槽位（结构化参数）
  → 数量成为可校验的硬约束
```

### 2.2.2 为什么打断要记录"说到哪"（合理推断）

**详细解释**：
- 打断时如果上下文记录 LLM 的完整回答：AI 以为自己讲完了
- 但用户实际只听到一半——双方对"已说内容"的认知错位
- 后续对话基于错位上下文 → 越聊越偏
- 正确做法：记录 TTS 实际播放位置，上下文只包含用户真正听到的内容

### 2.2.3 为什么 VAD 阈值要调优（合理推断）

**详细解释**：
- 太敏感：环境噪音触发打断 → AI 说话频繁被"假打断"
- 太钝：用户抢话不生效 → 打断体验差
- 平衡点：连续有声时长 + 能量阈值组合
- 这是实时语音系统的经典调参问题

## 2.3 性能与质量原因

### 2.3.1 为什么首句要短（合理推断）

**详细解释**：
- 首句短 → TTS 快速出声 → 用户感知延迟极短
- 短句同时缓冲后续长内容的生成时间
- 落地在陈妮的对话 prompt 中，与出题槽位配合（开场白不计入出题数量）

### 2.3.2 为什么角色边界放基础设施层（真实原因）

**来源**：git 提交记录 - `a448f1b`、`cf059cc`

**提交信息原文**：
```
a448f1b | 2026-07-31 | 张梦宇 | 拒绝执行用户非面试相关请求
cf059cc | 2026-07-31 | 张梦宇 | 调整安全合规和角色定位prompt
```

**详细解释**：
- 语音入口更容易被闲聊化——对着麦克风随口问比打字更随意
- 角色边界依赖业务 prompt 自觉不可靠——业务 prompt 高频迭代，容易漏
- 放基础设施层（张梦宇的链路层）：统一生效，不受业务迭代影响

## 2.4 工程实现原因

### 2.4.1 为什么三层分工（真实原因，提交归属支撑）

**详细解释**：
- 张梦宇：voice-demo 分支、默认启动、安全合规 → 链路层
- 陈妮：出题方向、难度自适应、槽位 → 对话策略层
- yitong：流式、点评、追问、埋点、耗时 → 集成体验层
- 三层各自高频迭代互不阻塞——60 天 60+ 次语音提交的组织基础
- 若混在一起：策略改动可能破坏链路，体验调优可能改动策略结构 → 协作成本爆炸

### 2.4.2 为什么上下文要裁剪（真实原因）

**来源**：git 提交记录 - `93a0dd7`

**提交信息原文**：
```
93a0dd7 | 2026-08-04 | yitong | 语音上下文裁剪
```

**详细解释**：
- 20+ 轮语音对话 + 工具产物会把上下文撑爆（详见 02 号文档）
- 不裁剪：长面试必然超限中断
- 裁剪保证"一场完整面试"的产品承诺

## 2.5 业务价值原因

### 2.5.1 为什么深度追问成为默认（真实原因 + 合理推断）

**来源**：git 提交记录 - `7607626`

**提交信息原文**：
```
7607626 | 2026-08-10 | yitong | 出题策略默认改为深度追问
```

**详细解释**：
- 从 07-28 调整、07-31 强化到 08-10 成为默认——一个半月验证期
- 追问是面试的核心价值：念题库谁都会，基于回答的追问才体现 AI 含金量
- 与错题本联动：追问暴露的薄弱点是错题本素材（`551de3b`）
- 与"每次只出一题"互相成就：一题一答一追问 = 真实面试节奏

### 2.5.2 为什么"面试感"值得这么多约束（合理推断）

**详细解释**：
- 语音面试产品的卖点是"像真实面试"——临场感、节奏感、专业感
- 任何破坏面试感的行为（批量出题、边面边评、闲聊化）都直接损害卖点
- 因此行为约束不是锦上添花，是产品定位的必然要求

## 3. 总结

### 3.1 核心原因总结

1. **流式是必选项**（真实）：非流式 6-8s 延迟不可接受
2. **单一 prompt 源**（真实）：多份 prompt 不同步的痛点被三条提交证明
3. **点评后置**（真实）：提交原文给出完整决策理由
4. **每次一题**（真实）：LLM 批量出题倾向需要三级约束

### 3.2 技术原因总结

1. **约束三级演进**（真实）：prompt → 强化 → 结构化槽位
2. **打断记录播放位置**（合理推断）：防止上下文错位
3. **角色边界基础设施化**（真实）：不受业务迭代影响
4. **上下文裁剪**（真实）：长面试不超限

### 3.3 业务价值总结

1. **面试临场感**（真实）：首字节 <1s + 真实节奏
2. **产品差异化**（真实）：深度追问 + 点评后置
3. **协作效率**（真实）：三层分工支撑高密度迭代
