**来源**：git 提交记录 - `772a2ee`

**提交信息原文**：
```
772a2ee | 2026-08-08 | 11099826 | feat: LLM scope意图分类兜底，company文件名去重，CSS修复
```

**详细解释**：
- scope 判定（"用户想改简历的哪部分"）用规则无法穷举——用户表述千变万化
- "LLM scope意图分类兜底"：规则判得了的走规则（快且确定），判不了的交给 LLM 分类
- 这是"规则 + 模型"双层架构：规则保下限，模型兜上限

**技术对比**：
```
纯规则判定：
- 快、确定，但覆盖率有限
- 用户换个说法就判不了

纯 LLM 判定：
- 覆盖率高，但慢、概率性、有成本

规则 + LLM 兜底（最终方案）：
- 规则命中 → 直接用（多数场景）
- 规则未命中 → LLM 分类（少数场景）
- 兼顾确定性、覆盖率与成本
```

### 2.2.3 为什么日期要用 canonical form（合理推断）

**详细解释**：
- 15+ 模板可能用不同显示方式（"2020.03" / "2020 年 3 月"）
- 但存储层必须只有一种形态（YYYY-MM / 至今），否则比较、排序、去重都无法进行
- 渲染时按需转换显示形态——与 01 号文档的日期归一化（`_format_date_range`）配套

## 2.3 性能与质量原因

### 2.3.1 为什么"拒绝渲染"改"降级全量渲染"（真实原因）

**来源**：git 提交记录 - `fb29509`

**提交信息原文**：

**详细解释**：

- 新策略：降级全量渲染——宁可全量重渲（慢一点、粗一点），不能没有产物
- 与 01 号文档的降级哲学一致：核心交付路径永远要有产物

### 2.3.2 为什么 auto_compress 默认 False（真实原因 + 合理推断）

**来源**：git 提交记录 - `e4117a9`、`20722c6`

**提交信息原文**：
```

```

**详细解释**：
- "auto_compress默认False"是明确的产品决策：自动压缩默认关闭
- 推断原因：自动压缩曾误删用户内容，`20722c6` 的"约束"就是治理
- 简历内容对用户是资产——宁可一页放不下，不能擅自删
- 压缩必须是用户显式选择，且"精准控制"（只压可压的，不碰核心内容）

## 2.4 工程实现原因

### 2.4.1 为什么模板要"shared 组件 + 差异化样式"（真实原因）

**来源**：git 提交记录 - `22e8097`（统一渲染逻辑）+ 代码库现状（resume_templates/）

**详细解释**：
- 共享组件（教育块、工作块）保证行为一致——bullet 格式化、字段渲染逻辑只有一份
- 差异化样式（CSS）保证视觉多样——15+ 模板各有风格
- 新模板 = 复用 shared 组件 + 新写 CSS → 小时级交付

### 2.4.2 为什么 Word 模板损坏要有兜底（真实原因）

**来源**：git 提交记录 - `9609b3a`

**提交信息原文**：
```
9609b3a | 2026-08-07 | 11099826 | fix: 模块顺序重排算法修复 + Word 模板损坏兜底 + 字段去重增强
```

**详细解释**：
- Word 模板文件（.docx）可能损坏（文件本身或处理过程）
- 无兜底时：模板损坏 = 导出失败 = 用户拿不到 Word 版
- 有兜底：降级到其他渲染路径，不阻塞交付
- 原则：交付链路的每个环节都要有退路

## 2.5 业务价值原因

### 2.5.1 为什么契约值得作为团队公共接口（合理推断）

**详细解释**：
- 契约是 LLM 侧（提取/prompt 维护者）与渲染侧（模板开发者）的协作界面
- 没有契约：两侧任何变更都要协调对方 → 协作成本高、事故多
- 有契约：两侧在契约边界内独立演进 → `b2384eb` 加 8 个字段不动其他模板就是证明

### 2.5.2 为什么"压缩不删内容"是产品底线（合理推断）

**详细解释**：
- 简历内容凝结了用户的经历与心血——擅自删除是信任级事故
- "一页"是排版目标，不是内容目标——排版问题应该用排版手段解决（间距、字号），不是删内容
- `e4117a9` 的"精准控制"方向：压缩的是排版空间，不是用户内容

## 3. 总结

### 3.1 核心原因总结

1. **静默丢失必须根治**（真实）：契约层显式处理字段不一致，不再静默吞掉
2. **渲染逻辑收敛共享层**（真实）：统一 bullet、PDF/Word 一致
3. **横切逻辑放对层**（真实）：scope 迁移工具层的教训
4. **降级优于拒绝**（真实）：核心交付永远有产物

### 3.2 技术原因总结

1. **主字段/弱字段分离**（真实）：演进弹性，弱字段扩展不波及主字段
2. **规则 + LLM 双层**（真实）：scope 判定兼顾确定性与覆盖率
3. **日期 canonical**（合理推断）：存储单一形态，渲染按需转换
4. **shared + 差异化**（真实）：行为一致 + 视觉多样

### 3.3 业务价值总结

1. **扩展性**（真实）：新模板小时级、新字段零波及
2. **交付可靠**（真实）：零内容丢失、模板损坏有兜底
3. **用户信任**（真实）：AI 标记语义准确、压缩不删内容
