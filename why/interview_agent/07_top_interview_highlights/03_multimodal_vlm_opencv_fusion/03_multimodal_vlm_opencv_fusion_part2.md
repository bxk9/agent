4. 每个环节 debug 日志，可按 trace_id 回查
```

### 4.5 边界 case 处理

**Case 1：头像误检（`1ebfb3f` 的根治）**
```
场景：公司 logo 被 OpenCV 误检出类人脸特征
处理：VLM 语义否决 → 排除
关键：单靠 OpenCV 必误检，单靠 VLM 也曾误检（1ebfb3f）→ 双路互相约束
```

**Case 2：头像失效（`86a54a7` 的根治）**
```
场景：提取出的头像链接打不开/图像损坏
处理：上传后 quality_check 校验产物可用性，不合格不交付不缓存
```

**Case 3：脏缓存清理**
```
场景：修复上线前已有脏结果在缓存中
处理：修复提取逻辑必须同时回答"历史脏缓存怎么办"——失效旧缓存或加版本键
教训：只修算法不清缓存 = 修复等于没修（用户请求仍命中旧缓存）
```

**Case 4：纯文字简历**
```
场景：简历根本没有头像图片
处理：fallback_no_avatar() 走无头像版式，而非产出空白占位
背景：9639b4f 点名"纯文字兜底质量低下"，兜底版式专门优化过
```

## 6. 技术亮点总结

### 6.1 创新性

1. **CV × LLM 互补融合**：几何证据与语义证据互相约束，单路失败模式被对方拦截
2. **缓存污染防御**：把"异常产物不进缓存"作为提取链路的一等约束
3. **评分降级闭环**：提取 → 评分 → 校验 → 降级，每个环节都有退路

### 6.2 技术深度

1. **多模态协同**：OpenCV 本地检测 + VLM 云端语义的分工与融合决策
2. **缓存一致性**：链接时效、脏缓存清理、版本化失效
3. **兜底工程**：无头像/低质量/异常三类兜底路径

### 6.3 业务价值

1. **视觉可信度**：头像是简历最显眼的元素，正确率直接关系产品信任
2. **错误不扩散**：缓存治理保证一次异常不演变为持续事故
3. **全形态覆盖**：从证件照到纯文字简历都有体面产出

### 6.4 方法论抽象与迁移（原文档保留部分）

**抽象出的通用方法论——"双证据融合 + 质量门禁"**：

1. **失败模式正交的两路才值得融合**：VLM 误检 vs OpenCV 漏检是正交的；如果两路失败模式重叠，融合只增加成本不增加可靠性
2. **确定性算法在前、概率模型在后**：成本与精度双重收益
3. **产物必须过质量门禁才能进缓存/下游**：缓存放大错误，门禁是唯一防线
4. **修复必须包含存量治理**：只修算法不清历史脏数据 = 修复无效

**可迁移场景**：

| 场景 | 迁移点 |
|:---|:---|
| 证件识别（身份证/营业执照） | 检测框 + 语义确认双路 |
| 商品主图提取 | 几何候选 + VLM 质量判断 |
| 文档印章/签名检测 | 传统 CV 先筛 + 语义后判 |
| 任何"模型产物 + 缓存"系统 | 质量门禁 + 存量治理 |

**反例警示**：
- **反例 1**：调参救场（`d9249b1`）——单路方案的参数空间救不了架构缺陷
- **反例 2**：跳过产物校验直接缓存 → 一次异常污染所有后续请求
- **反例 3**：兜底产物无质量门槛（早期纯文字兜底被点名"质量低下"）

## 7. 面试问答准备

### Q1: 为什么要双路，单路不行吗？

**A**：
1. 实证：纯 VLM 时期三天五起事故（误检 `1ebfb3f`、失效 `86a54a7`），调参（`d9249b1`）救不回来
2. 原理：VLM 擅长语义不擅长定位，OpenCV 擅长定位不懂语义，失败模式正交互补
3. 成本：OpenCV 本地先筛，VLM 只确认候选，比全图 VLM 便宜

### Q2: 两路结果冲突怎么办？

**A**：
1. OpenCV 检出 + VLM 否决 → 排除（语义优先，防误检）
2. OpenCV 漏检 + VLM 找到 → 采纳（语义兜底，防漏检）
3. 双路都无 → 无头像兜底路径
4. 原则：宁可漏检不可误检——头像是没有可以接受，错了不可接受

### Q3: 缓存污染怎么防？

**A**：
1. 入口控制：质量评分不合格的产物不写缓存（`9639b4f`）
2. 存量治理：修复算法同时清理/失效历史脏缓存，否则修复等于没修
3. 时效治理：缓存的 VFS 链接会过期，命中时校验时效（`f13d71e`）
4. 可追溯：debug 日志按 trace_id 回查（`5288ccf`）

### Q4: 无头像简历怎么处理？

**A**：
1. 早期"纯文字兜底质量低下"（`9639b4f` 点名）——空白占位很难看
2. 治理：专门的无头像版式，版式自适应（头像位收起，个人信息区重排）
3. 原则：兜底产物也要有质量门槛

### Q5: 这个方案的迁移价值？

**A**：
1. 任何"视觉元素提取 + 质量敏感"的场景：证件识别、商品主图提取、文档印章检测
2. 迁移要点：确定性算法先筛 + 语义模型后判 + 产物校验后才缓存
3. 反例警示：跳过产物校验直接缓存 = 一次异常污染所有后续请求

## 9. 总结

VLM + OpenCV 双路头像提取是一个典型的**事故驱动的多模态融合案例**，展示了：

1. **失败模式分析**：从三天五起事故中识别出单路方案的根本缺陷
2. **多模态协同设计**：几何证据 × 语义证据的正交互补
3. **兜底工程**：缓存治理 + 评分降级 + 无头像版式的完整退路体系

**一句话总结**：以"OpenCV 几何先筛 + VLM 语义后判"的双路融合根治头像误检/失效，以"合格才缓存 + 评分降级"根治异常产物扩散，三天内完成从事故响应到体系化治理的闭环。
