**关键决策 1：OpenCV 在前、VLM 在后**

OpenCV 本地毫秒级零成本先筛候选，VLM 只确认少量候选——成本差异决定顺序；两路失败模式正交（VLM 误检 vs OpenCV 漏检），互相兜底。

**关键决策 2：宁可漏检不可误检**

头像缺失可以接受（很多简历本来没头像），头像错误不可接受（用户第一眼就看到）。因此 VLM 否决权优先：OpenCV 检出但 VLM 否决 → 排除。

**关键决策 3：合格产物才进缓存**

一次异常产物进缓存 = 该简历后续所有请求全错。质量评分不合格只返回不缓存；修复算法必须同时清理历史脏缓存，否则修复等于没修。

**淘汰的方案**：

| 淘汰方案 | 淘汰原因 |
|:---|:---|
| **纯 VLM** | `1ebfb3f`（误检）`86a54a7`（失效）直接证伪；VLM 擅长描述不擅长定位 |
| **纯 OpenCV** | 简历头像风格多变（圆形裁剪/插画/艺术照）漏检率高；无法回答"是头像还是合影"的语义问题 |
| **VLM 直接输出坐标** | 坐标精度与格式稳定性差；与 01 号文档同源教训——LLM 精确结构化输出不可信 |

## 2. 项目背景与问题定义

### 2.1 业务场景

AI 简历生成的头像处理链路：

```
简历原稿（PDF/DOCX/图片）
    ↓
头像区域检测与提取
    ↓
头像存入 VFS（claw:// 协议链接）
    ↓
15+ 模板渲染头像位（HTML/DOCX/PDF）
```

**头像的特殊性**：
- 简历头像是**用户可直接感知的视觉元素**——错了立刻被发现
- 头像形态高度多变：证件照、生活照、圆形裁剪、插画风、低清扫描件
- 部分简历根本没有头像（纯文字简历）——必须有兜底

### 2.3 优化目标

**核心问题**：如何让头像提取在多变形态下稳定正确，且错误不扩散？

**量化目标**：
- 误检率收敛（不把 logo/图表当头像）
- 提取产物可用（链接有效、图像完整）
- 脏结果不进缓存、历史脏缓存可清理
- 无头像简历有体面的兜底

## 3. 技术方案设计

### 3.1 核心思路

**VLM + OpenCV 双路融合**：

```
简历页面图像
    ├──▶ OpenCV 人脸检测（本地，毫秒级）→ 候选人脸框集合
    │         几何证据：这里有一张人脸
    │
    └──▶ VLM 语义判断（LLM 调用）→ 区域语义确认
              语义证据：这是不是用户头像、质量够不够
    
融合决策：
  OpenCV 检出 + VLM 确认 → 高置信头像
  OpenCV 漏检 + VLM 找到 → 语义兜底（非标准头像）
  OpenCV 检出 + VLM 否决 → 排除（合影/插图）
  双路都无 → 无头像兜底路径
```

**关键挑战**：
1. 两路结果如何融合决策？
2. 提取结果如何缓存且不污染？
3. 无头像/低质量时如何兜底？

### 3.2 双路互补规则表

**失败模式互补表**：

| 维度 | VLM | OpenCV 人脸检测 |
|:---|:---|:---|
| 擅长 | 语义理解（证件照 vs logo） | 几何定位（人脸框坐标精确） |
| 失败模式 | 误检（`1ebfb3f`）、输出不稳 | 侧脸/低清/艺术照漏检 |
| 成本 | 高（一次 LLM 调用） | 极低（本地毫秒级） |
| 确定性 | 概率性 | 确定性算法 |

**融合决策表**：

| OpenCV 结果 | VLM 结果 | 决策 |
|:---|:---|:---|
| 检出 | 确认 | 采纳（高置信） |
| 检出 | 否决 | 排除（防误检，语义优先） |
| 漏检 | 找到 | 采纳（语义兜底，防漏检） |
| 无 | 无 | 无头像兜底路径 |

## 4. 核心实现细节

### 4.1 OpenCV 检测路

**引入时刻**（真实）：`a867570`（08-04 "OpenCV 人脸检测库"）与 `929a58a`（修复图像版式提取）**同日提交**——版式提取翻车当天引入 OpenCV。

```python
# OpenCV 人脸检测（示意，对应 a867570 引入的检测库）
import cv2

def detect_face_candidates(page_image):
    """本地快速给出候选人脸框，零 LLM 成本"""
    detector = cv2.CascadeClassifier(
        cv2.data.haarcascades + "haarcascade_frontalface_default.xml"
    )
    gray = cv2.cvtColor(page_image, cv2.COLOR_BGR2GRAY)
    faces = detector.detectMultiScale(
        gray,
        scaleFactor=1.1,   # d9249b1 "头像提取修改参数"调的就是这类参数
        minNeighbors=5,
        minSize=(30, 30),
    )
    return faces  # 候选框集合，交给 VLM 做语义确认
```

### 4.3 融合决策与兜底

```python
async def extract_avatar(page_image, resume_url):
    # 1. OpenCV 候选
    candidates = detect_face_candidates(page_image)
    
    # 2. VLM 逐个确认
    confirmed = []
    for box in candidates:
        verdict = await vlm_confirm_avatar(crop(page_image, box))
        if verdict.is_avatar and verdict.quality >= QUALITY_THRESHOLD:
            confirmed.append((box, verdict))
    
    # 3. 决策
    if confirmed:
        best = max(confirmed, key=lambda x: x[1].quality)
        avatar = upload_to_vfs(crop(page_image, best[0]))
        if quality_check(avatar):      # 产物校验（防 86a54a7 头像失效）
            cache_put(resume_url, avatar)   # 合格才进缓存（防 9639b4f 污染）
            return avatar
        return fallback_no_avatar()    # 降级
    else:
        # 双路都无 → 无头像兜底（治理 9639b4f "纯文字兜底质量低下"）
        return fallback_no_avatar()
```

# 缓存里存的不只是"值"，还有"链接的时效性"
def cache_get(resume_url):
    cached = store.get(resume_url)
    if cached is None:

    if is_vfs_link_expired(cached.avatar_url):
