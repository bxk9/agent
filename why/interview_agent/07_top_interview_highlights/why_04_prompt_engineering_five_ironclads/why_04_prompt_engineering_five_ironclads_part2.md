铁律要求：直接采用转写原文形态，不做任何换算
```

### 2.2.2 为什么同音变体要"容错但有边界"（合理推断）

**详细解释**：
- ASR 同音错字是必然存在的（"二叉树" → "二插树"）
- 两个极端都不可取：
  - 严格按原文引用 → 错字原样进报告，出现"二插树"笑话
  - 自由纠正 → LLM 过度纠错，把对的改错（"二插树" 纠成 "红黑树"）
- 容错边界：识别同音变体、按正确术语呈现、但不臆造原文没有的内容

**边界示例**：
```
允许：二插树 → 二叉树（同音变体纠正）
允许：哈稀 → 哈希（术语还原）
禁止：二插树 → 红黑树（过度推断，改变了内容）
禁止：原文没提 Redis，LLM 补充"候选人熟悉 Redis"（臆造）
```

### 2.2.3 为什么 ASR 超时是 600s（真实原因 + 合理推断）

**来源**：git 提交记录 - `e63ab74`

**提交信息原文**：
```
e63ab74 | 2026-06-09 | 陈乾 | ASR超时时间设为600s
```

**详细解释**：
- 600s（10 分钟）超时说明面试录音转写是长耗时任务
- 与司棋侧 A2A 超时 600s（`8b03975`）是同一个数字——团队对"长任务 10 分钟上限"有共识
- 长转写意味着大文本 + 质量波动大，下游 prompt 必须防御性设计（数字铁律、同音铁律的另一个动因）

## 2.3 性能与质量原因

### 2.3.1 为什么选择"prompt 铁律 + 代码拦截"双保险（真实原因）

**来源**：git 提交记录 - `05399d4` + `023a47b`（同日提交）

**详细解释**：
- 两条提交同日落地（08-07），说明是配套设计而非先后补救
- prompt 铁律降低违规概率：多数请求一次通过，控制重试成本
- 代码拦截保证确定性：漏网的必然被挡住
- 单用任何一个都有致命缺陷（见技术对比）

**成本分析**：
```
只有代码拦截：
- LLM 漏题率高时，大量请求触发重试 → 成本翻倍、延迟翻倍
只有 prompt 铁律：
- 概率性约束无法归零 → 总有漏题流向用户
双保险：
- prompt 把违规率压到低位（多数一次通过）
- 代码兜住剩余漏网（确定性）
- 总成本最优
```

### 2.3.2 为什么移除链接域名替换而不是修复（真实原因）

**来源**：git 提交记录 - `92bc8e6`

**提交信息原文**：
```
92bc8e6 | 2026-08-04 | 陈乾 | 移除复盘报告链接域名替换流程
```

**详细解释**：
- "移除"而不是"修复"——说明该环节被判定为负价值
- 域名替换的本意可能是环境适配，但实际会把正确链接改坏（合理推断）
- 交付链路上每个经手环节都是潜在故障点，能删就删——减法思维

## 2.4 工程实现原因

### 2.4.1 为什么音频链接要加开关和日志（真实原因）

**来源**：git 提交记录 - `341e183`

**提交信息原文**：
```
341e183 | 2026-08-04 | 陈乾 | 新增 GET_AUDIO_PUBLIC_URL 开关，开启时音频文件额外签发 public 短链并记录日志
```

**详细解释**：
- 复盘报告交付包含音频回听链接，链接签发是交付链路的一环
- 加开关：能力可控（不同环境/场景可关闭）
- 记录日志：链接签发可追溯，出问题能回查
- 与 VFS 侧"所有接口加请求日志"（`c669057`）是同一治理思路

### 2.4.2 为什么拦截要"记录原因"（真实原因）

**来源**：git 提交记录 - `05399d4`

**提交信息原文**：
```
05399d4 | 2026-08-07 | 陈乾 | feat(复盘报告): 交付前拦截逐题分析漏题并记录原因
```

**详细解释**：
- 提交标题明确包含"并记录原因"——这不是顺手的日志，是设计目标
- 漏题成因多样（上下文过长/题号格式/转写缺失），不同成因需要不同治理
- 记录原因让拦截成为改进的输入：统计成因分布 → 针对性优化 prompt 或素材组织

## 3. 总结

### 3.1 核心原因总结

1. **漏题必须交付前拦截**（真实）：prompt 强调无法归零，交付物需要确定性闸门
2. **校验前置到落盘**（真实）：落盘是交付起点，闸门设在此处坏产物到不了用户
3. **素材可溯源**（真实）：事实围栏的前提，复盘产品的一贯要求
4. **双保险架构**（真实）：prompt 降概率 + 代码保确定，同日配套落地

### 3.2 技术原因总结

1. **数字溯源**（真实+推断）：ASR 数字漂移 + LLM 心算会错上加错
2. **同音容错有边界**（合理推断）：两个极端都不可取，边界是"纠正但不臆造"
3. **600s 转写超时**（真实）：长任务共识参数，转写质量波动催生防御性 prompt
4. **链接治理**（真实）：加开关加日志，危险环节直接移除

### 3.3 业务价值总结

1. **交付可信**：零漏题、坏报告零落盘
2. **信任保护**：事实围栏杜绝"AI 没听我说话"
3. **可审计**：校验与拦截全留痕，问题可归因
