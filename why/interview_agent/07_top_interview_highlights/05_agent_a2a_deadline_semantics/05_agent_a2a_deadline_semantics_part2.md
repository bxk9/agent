止损能力：600s 静默上限 → 卡死任务必然释放
后续验证：08-13 的心跳修复（ab4416e "修复主Claw 180s 超时断连"）
          再次验证同一原理——活性靠持续消息证明，不靠一次性声明
```

## 6. 技术亮点总结

### 6.1 创新性

1. **静默超时语义**：把"超时度量什么"从总时长改为静默时长，根治长任务误杀
2. **错误优化的纠错**：识别并移除 lastChunk 缩短逻辑——优化也可能引入 bug
3. **多通道产物送达**：三级通道兜底，单点故障不丢产物

### 6.2 技术深度

1. **分布式协议理解**：活性判断、心跳本质、优雅关闭
2. **状态机设计**：WebSocket 连接状态 × A2A 任务状态 × 超时计时器三者交织
3. **排查纪律**：日志先行（`ab71cda` 第一步就是补日志），否则无从下手

### 6.3 业务价值

1. **交付确定性**：用户请求生成文档，生成的必然送达
2. **长任务友好**：几分钟的文档生成不再被超时误杀
3. **止损可控**：卡死任务 600s 内释放，不占用资源

### 6.4 方法论抽象与迁移（原文档保留部分）

**抽象出的通用方法论——"活性���持续消息证明"**：

1. **超时应该度量静默，不是总时长**：对长任务，总时长超时必然误杀
2. **不信任对端的声明性信号**：lastChunk、progress 百分比都可能撒谎，只有"还在收到消息"是硬证据
3. **交付要多通道**：关键产物不能依赖单一传递通道
4. **日志先行**：难复现的分布式 bug，第一步永远是补全日志

**可迁移场景**：

| 场景 | 迁移点 |
|:---|:---|
| 微服务长任务调用 | 静默超时语义 |
| 消息队列消费 | 心跳与活性判断 |
| 文件上传/下载 | 多通道 + 断点保留 |
| 任何 Agent 间通信 | 产物送达的多通道兜底 |

**反例警示**：
- **反例 1**：lastChunk 缩短 deadline（`0d3d2dd` 移除）——把控制权交给不可信的对端信号
- **反例 2**：超时即丢弃全部已收产物——止损不应扩大损失
- **反例 3**：直接断连不握手——对端误判事故，引发连锁重试

## 7. 面试问答准备

### Q1: 为什么超时要用静默语义？

**A**：
1. 文档生成是长任务（几十秒到几分钟），总时长超时必然误杀正常任务
2. 静默超时只惩罚真正卡死的任务：只要还在收到进度消息，deadline 顺延
3. 本质：超时度量的是"对端失联多久"，不是"任务跑了多久"
4. 实证：`b05db56`（确立）+ `02914d8`（修复三个重置点 bug）

### Q2: lastChunk 缩短 deadline 为什么是错的？

**A**：
1. 它信任了对端的声明性信号——A2A 服务端标记的"最后一块"并不可靠
2. 后果：提前退出，后续 artifact 丢失（`0d3d2dd` 提交原文）
3. 教训：分布式系统中，对端的"我做完了"声明不能替代"我还在发消息"的事实
4. 这与 TCP 不信任 FIN 之前的数据声明、要靠 ACK 确认是同构的

### Q3: 这个 bug 为什么修了 12 天 7 次提交？

**A**：
1. 难复现：只在"文档生成足够慢 + 产物足够多"时触发
2. 多通道干扰：产物路径有三个来源，修一个通道另一个还在漏
3. 状态机复杂：连接状态 × 任务状态 × 计时器交织
4. 修复引入新问题：`0d3d2dd` 修的就是上一个"优化"引入的 bug
5. 所以第一步是补日志（`ab71cda`）——没有日志根本无从下手

### Q4: 超时后已收到的产物怎么办？

**A**：
1. 保留已收部分，只标记任务未完成——止损不应扩大损失
2. 优雅关闭连接（`37a9175`），让对端正常收尾
3. 上报超时事件，供后续分析对端为何静默

### Q5: 600s 这个参数怎么定的？

**A**：
1. `8b03975` 把 A2A timeout 定为 600s，与 ASR 超时（`e63ab74`）相同
2. 团队对"长任务 10 分钟上限"形成共识参数
3. 静默语义下 600s 是"完全失联"的容忍上限，不是任务时长上限——有进度的任务不受此限

## 9. 总结

A2A deadline 语义修复是一个典型的**分布式协议纠错案例**，展示了：

1. **协议语义理解**：超时度量静默而非总时长，活性靠持续消息证明
2. **完整事故链复盘**：12 天 7 次提交，每一步都有 git 证据
3. **工程纪律**：日志先行、多通道兜底、优雅关闭

**一句话总结**：以"收到进度即重置 deadline"的静默超时语义替代错误的总时长/lastChunk 语义，配合三级产物通道与优雅关闭，把文档 Agent 的产物送达从"看运气"变成"确定性"。
