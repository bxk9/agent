## 1. 核心概览（原文档保留部分）

### 1.1 一句话摘要

复盘报告的原始素材是**面试录音的 ASR 转写文本**——同音错字、数字漂移、转写噪声是天然伴生物；我把两个月里逐类暴露的事故固化为**五大铁律**：数字精确、硬闸校验、全覆盖不漏题、事实围栏、同音变体容错，并坚持"prompt 铁律降概率 + 代码拦截保确定"的双保险架构。

**关键决策 1：prompt 铁律 + 代码他律双保险**

prompt 强调只能降低违规概率，不能归零；复盘报告是交付物，必须有确定性闸门。所以"交付前拦截"用代码核对题目清单，缺题即拦截重试，并记录原因供归因。

**关键决策 2：铁律按失败模式逐条固化**

每条铁律对应一类真实事故，不做"大而全"的笼统约束——数字漂移、同音错字、漏题、无依据点评、脏产物，各自有独立的规则与校验。

**关键决策 3：交付链路的减法思维**

`92bc8e6`（移除链接域名替换流程）：发现替换逻辑会把正确链接改坏，与其打补丁不如直接移除——能删的环节就删。

**淘汰的方案**：

| 淘汰方案 | 淘汰原因 |
|:---|:---|
| **只靠 prompt 自律** | 概率性约束无法归零，漏题仍会发生且无法归因 |
| **只靠代码校验** | 校验只能拦截不能修正，LLM 违规率高时重试成本爆炸，必须 prompt 先降概率 |
| **人工审核交付** | 复盘报告是高频自动交付物，人工不可扩展 |

## 2. 项目背景与问题定义

### 2.1 业务场景

面试复盘报告的生成链路：

```
用户完成一场面试（文字或语音）
    ↓
语音面试：录音 → ASR 转写（48f4d39 接入，超时 600s）
    ↓
复盘素材 = ASR 转写文本 + 题目清单 + 错题本记录
    ↓
LLM 生成复盘报告（逐题分析 + 整体评价 + 改进建议）
    ↓
校验闸门（023a47b/05399d4）→ 落盘 → 推送用户
```

**复盘报告的产品地位**：
- 用户完成面试后，复盘报告是"这次练习值不值"的最终判断依据
- 报告错误（漏题、幻觉、错字）直接等于产品不合格
- 因此规则必须是**铁律级**（违反即拦截），而非建议级

### 2.2 失败模式分析

**五类事故与五大铁律的对应关系**：

| 失败模式 | 典型表现 | 对应铁律 | 证据 |
|:---|:---|:---|:---|
| 逐题分析漏题 | 用户答 8 题报告只点评 6 题 | **全覆盖** | `05399d4` |
| 坏报告落盘 | 校验未过就推送用户 | **硬闸** | `023a47b` |
| 数字漂移 | ASR 转写数字错 + LLM 心算幻觉 | **数字精确** | ASR 链路（`48f4d39`） |
| 无依据点评 | 点评了用户没说过的话 | **事实围栏** | 素材可溯源传统（`1df495b`） |
| 同音错字 | "二叉树"转成"二插树"进报告 | **同音变体** | ASR 链路 |

### 2.3 优化目标

**核心问题**：如何让 LLM 基于嘈杂的 ASR 转写文本，产出"零漏题、零幻觉、零错字"的可交付报告？

**量化目标**：
- 逐题分析覆盖率 100%（交付前代码核对）
- 坏报告零落盘（校验硬闸）
- 关键数字可溯源到转写原文

## 3. 技术方案设计

### 3.1 核心思路

**双保险架构**：

```
【prompt 侧：五大铁律】降低违规概率（减少重试成本）
    ↓
【代码侧：交付闸门】保证最终确定性（拦截 + 归因）
    ↓
交付用户
```

### 3.2 五大铁律规则表

| 铁律 | 规则内容 | 防御的失败模式 | 校验方式 |
|:---|:---|:---|:---|
| **全覆盖** | 逐题分析必须覆盖题目清单全部题目 | 漏题 | 代码核对题目清单，缺题拦截重试 |
| **硬闸** | 校验不过不许落盘 | 坏报告推送 | save_review_report 前置校验 |
| **数字精确** | 关键数字必须溯源原文，禁止心算/估算 | 数字漂移 | 数字字段与原文比对 |
| **事实围栏** | 每条点评必须对应转写原文依据 | 无依据点评 | 依据缺失则不写或标注"建议补充" |
| **同音变体** | 识别 ASR 同音变体，按正确术语呈现，不臆造 | 同音错字 | 术语表 + 容错边界 |

## 4. 核心实现细节

### 4.1 铁律 1：全覆盖——交付前拦截

**实现**（真实，commit `05399d4`"交付前拦截逐题分析漏题并记录原因"）：

```python
def pre_delivery_check(report, question_list):
    """交付前核对逐题分析覆盖率"""
    analyzed = extract_analyzed_questions(report)
    missing = [q for q in question_list if q.id not in analyzed]
    
    if missing:
        # 拦截 + 记录原因（05399d4 原文要求"并记录原因"）
        logger.warning(
            f"review_report_blocked: missing_questions={missing}, "
            f"reason={classify_miss_reason(missing)}, trace_id={trace_id}"
        )
        return retry_with_explicit_list(question_list)  # 带完整题目清单重试
    return pass_to_save(report)
```

**为什么"并记录原因"很重要**：
```
漏题有多种成因：
- 上下文过长 → LLM 跳题
- 题号格式不一 → LLM 认为不是题目
- 转写缺失 → 该题无素材可分析
不记录原因就无法分类治理，拦截会变成无脑重试
```

### 4.2 铁律 2：硬闸——校验不过不落盘

**实现**（真实，commit `023a47b`"save_review_report 增加校验通过日志"）：

```python
def save_review_report(report):
    # 校验前置：不合格不落盘
    check_result = validate_report(report)
    logger.info(f"save_review_report: validation={'PASS' if check_result.ok else 'FAIL'}, "
                f"trace_id={trace_id}")
    if not check_result.ok:
        return reject_and_retry(report, check_result.errors)
    persist(report)
```

**校验通过与否都留痕**——这是审计与归因的基础。

### 4.3 铁律 3 & 5：数字精确 + 同音变体（ASR 输入治理）

**背景**（真实，ASR 链路提交）：

```
48f4d39 | 06-09 | 陈乾 | 新增asr工具 接入面试复盘链路
e63ab74 | 06-09 | 陈乾 | ASR超时时间设为600s
0f4c103 | 06-09 | 陈乾 | feat(agent): 解析 message.metadata.audioUrl，拼入 query 供面试复盘使用
```

**ASR 文本的两大顽疾与治理**：

```
顽疾 1：同音错字
  "二叉树" → "二插树"，"哈希" → "哈稀"
  治理边界（同音变体铁律）：
  - 识别同音变体 → 按正确术语呈现
  - 但不臆造原文没有的内容
  - 错误示例：把"二插树"纠正为"红黑树"（过度纠错）

顽疾 2：数字漂移
  ASR 对数字转写错误率高，"一千"与"1000"混用
  治理（数字铁律）：
  - 评分、题数、时长等关键数字必须溯源转写原文
  - 禁止 LLM 心算或估算
```

**600s 超时的含义**：`e63ab74` 说明面试录音转写是长耗时、大文本任务，转写质量波动大，下游 prompt 必须防御性设计。

### 4.4 铁律 4：事实围栏

```
规则：每条点评必须能对应到转写原文的依据
  有依据 → 正常点评
  无依据 → 要么不写，要么显式标注为"建议补充"
  
反例（必须拦截）：
  LLM 基于转写噪声脑补"候选人提到了 XX 经验"
  → 用户一看便知是幻觉 → 信任崩塌
  
旁证：1df495b（复盘素材来自错题本时按时间顺序展示）
  —— 团队对"素材与产物的对应关系"有强执念，素材可溯源是一贯要求
```
