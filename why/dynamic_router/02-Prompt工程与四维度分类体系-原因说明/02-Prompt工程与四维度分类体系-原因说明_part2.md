**隐式COT**：
```
# 推理步骤（强制执行，不得跳过）
在输出标签前，请在内心按顺序完成以下判断：
   - ① 基于分类标准、工具定义、query和history，确定[工具类型]，按优先级判定。
        · 历史延续优先：若history上一轮已锁定某工具（模型在追问该工具的参数，或刚执行过该工具），当前query默认视为该工具的参数补全或延续，按single处理。
        · query意图方向不明，或存在多个相似候选工具可承接（无论动宾是否完整），且history未锁定工具时，归pend+vague
        · 含并列连接结构的复合任务，整体按multi处理（含single与unsupported/qa/pend混合也归multi）。
   - ② 基于①的结论、工具定义和分类标准，判断[意图明确度]：
      · 若① ∈ {chat, qa, unsupported}，强绑定clear；若① = pend，强绑定vague。
      · 否则按vague > infer > lack > clear取最高档。
   - ③ 检查query中是否含"外部条件触发+待执行任务"结构，判断[指令类型]。
   - ④ 判断当前query是否含异常反馈（仅当前轮，且错源在模型而非用户改主意）。
然后再按顺序输出最终的4个标签。
```

**设计逻辑**：
```
为什么需要隐式COT？
- 引导模型按顺序思考
- 避免模型跳跃式思考
- 提高分类准确率

为什么是隐式COT而不是显式COT？
- 隐式COT：模型在内心思考，不输出思考过程
- 显式COT：模型输出思考过程，再输出结果
- 隐式COT节省token，提高推理速度
- 显式COT增加token，降低推理速度
```

# 输出要求 (绝对死线约束)
1. 输出格式: 必须且只能输出由4个小写英文单词组成的字符串，标签之间仅用1个空格' '分隔。

   - 位置2: clear, lack, infer, vague
   - 位置3: cond, norm
   - 位置4: abnormal, ok
